# 2018-12-18 松下镜头 AF 修复 —— 定位否定结果（v2.2 vs v2.3 同机型差分）

> 日期：2026-10-22
> 结论性质：**观察（静态）**，不含执行证据
> 意义：这是本项目首次拿到**同机型、同代码代、"修复前"与"修复后"两个版本**，
> 从而可以**证伪**此前的工作假设，把搜索方向从镜头 ID 结构彻底移开。

---

## 1. 背景

E-P5 官方更新说明（Dec.18 2018，v1.8）：

> Corrected issue of autofocus (AF) function not operating correctly when using the
> **"H-ES200" and "H-ES50200"** interchangeable lens produced by Panasonic.

此前工作把落点收敛到 E-P5 1.8 块 0 的「镜头 ID 两字节前缀比较链」
（`0x403B7989`，7 对）与「镜头厂商码表」（`0x403B5ACF`，10 项），
并留下两个候选补丁字节组：`{0xC1:0x80, 0xC1:0x00}` 与 `{0xC0:0xF1, 0xC0:0xE1}`。

**阻塞**：Wayback 只存档了 2012/2013 代机型每个型号的**最新一版**（本次已全量普查，
5 个域名 / 21,038 URL / 52 个 `.BIN`，确认无"修复前"版本），官方直链一律 403。

## 2. 新增基线（xdel.ru 镜像）

xdel.ru 的奥林巴斯固件档案（非 Wayback）提供了**同机型的历史版本**：

| 文件 | 版本 | 日期 | 相对 AF 修复 |
|---|---|---|---|

| `OLY_E_097_2100_0000_0000.BIN` | E-M5 v2.1 | Nov.13 2014 | 修复前 |
| **`OLY_E_097_2202_0000_0000.BIN`** | **E-M5 v2.2** | **Jan.28 2016** | **修复前（直接前一版）** |
| `OLY_E_097_2300_0000_0000.BIN` | E-M5 v2.3 | **Dec.18 2018** | **含修复** |

E-M5 (0970) 与 E-P5 (1080) 同为 **2012 代**机身、同一代代码库，
且 v2.3 与 E-P5 v1.8 **同日（Dec.18 2018）下发同一条修复文案**。

## 3. 观察结果

### 3.1 字节级差分：整包重编译，**不可用**

块 0 两版**长度完全相同**，但 **3,319,143 字节不同**，覆盖 349,129 个连续跨度，
从 `file 0x00000593` 一直分布到 `file 0x00CFB8D7`。

⇒ 三年间代码被**整体重编译并重排**（链接顺序/段布局变化），
**逐字节差分无法定位补丁**。这是本次差分无法直接给出答案的原因。

### 3.2 结构级差分：**镜头 ID 结构完全相同** ⇒ 关键否定结论

用 `tools/lens_compare.py` 做语义对照（比较链 + LENS_INFO 主表）：

| 结构 | E-M5 v2.2（修复前） | E-M5 v2.3（含修复） | 是否相同 |
|---|---|---|---|
| 前缀比较链（窗口 `0x904AA56E`） | `C1:80 C1:00 C0:F1 C0:E1 80:F1 81:E3 81:F1` (+1 误报) | 同左 | **完全相同** |
| 比较链条目数 | 7 | 7 | 相同 |
| LENS_INFO 主表记录数 | 106 | 106 | 相同 |
| LENS_INFO 唯一镜头 ID 数 | 105 | 105 | 相同 |
| 厂商码分组 | `60 / 70 / 80 / 81 / B0 / B1 / C0 / C1 / C2 / C3 / D0 / D1 / E0` | 同左 | 相同 |
| 集合差（两向） | 空 | 空 | — |

**⇒ 结论（观察级）**：

1. **2018-12-18 的松下镜头 AF 修复，既不在「镜头 ID 两字节前缀比较链」里，
   也不在「LENS_INFO 镜头主表」里。**
2. 这**证伪**了本项目此前的工作假设（落点在比较链的两个候选字节组
   `{C1:80, C1:00}` / `{C0:F1, C0:E1}`）。
3. 修复必然位于**镜头 ID 识别之后的环节**：AF 控制流程、每镜头的 AF 参数组、
   或镜头 I²C 应答处理（`LENS_ASKDATA_MODE_*`，34 个字段）。

### 3.3 旁证：E-M5 的比较链与 E-P5 完全相同

| 机型 / 版本 | 链长度 | 内容 |
|---|---|---|
| E-P5 1.8（含修复） | 7 | C1:80 C1:00 C0:F1 C0:E1 80:F1 81:E3 81:F1 |
| **E-M5 2.3（含修复）** | **7** | **完全相同** |
| **E-M5 2.2（修复前）** | **7** | **完全相同** |
| E-P3 1.6（含修复） | 4 | C1:80 C1:00 C0:F1 C0:E1 |

⇒ E-P5/E-M5 多出的 3 项（`80:F1`、`81:E3`、`81:F1`）是 **2012 代平台共有项**，
与松下修复无关；E-P3 之所以只有 4 项，是 **2011 代 vs 2012 代的平台差异**，
同样与松下修复无关。

## 4. 对后续方向的影响

| 原方向 | 状态 |
|---|---|
| 在比较链里找松下补丁字节 | ❌ **已证伪**（v2.2 vs v2.3 链完全相同） |
| 在 LENS_INFO 主表里加松下镜头 | ❌ **已证伪**（两版表完全相同） |
| 「每镜头 AF 参数在机身 mask ROM」 | ⚠️ 若属实，则**固件补丁无法新增镜头组**；需先证实 |
| AF 控制流程 / 每镜头 AF 参数组（在块 0 内） | ⬜ **当前最可能的方向** |
| 镜头 I²C 应答处理（`LENS_ASKDATA_MODE_*`） | ⬜ 次可能方向 |

公开旁证：`cmdada/em10-fw` 的 `notes/autofocus.md` 描述了机身侧
**约 12 组「每镜头 AF 参数块」**，打印
`fcs_act_mode, ap_target, ap_speed, wob_amp, wob_move, ofs_time, ofs_move,
iaf_target, iaf_speed, iaf_dist`。
**「新增一个松下镜头组」正是 2018 年 AF 修复会做的事** —— 这是下一步最值得追的结构。

## 5. 复现

```sh
# 差分（同机型修复前/后）
python tools/lens_compare.py \
  em5_2202=<fw>/OLY_E_097_2202_0000_0000.BIN \
  em5_2300=<fw>/OLY_E_097_2300_0000_0000.BIN

# 字节级差分（显示整包重编译）
python tools/fw_diff.py <v2.2.BIN> <v2.3.BIN> em5_2202 em5_2300
```
