### 差分管线的正确性已被独立验证

E-M5 v2.2 → v2.3 的语义差分自动找出了 **版本号上报函数**：

```
函数 前@00ccf830  ~ 0x2202,D0  ->  0x2300,D0     (相似度 0.997, 只改 1 个 token)
函数 前@00cbc84f  ~ 0x2202,D2  ->  0x2300,D2     (相似度 0.998, 只改 1 个 token)
```

`0x2202` = E-M5 v2.2，`0x2300` = E-M5 v2.3 —— **差分工具精确地自动定位到了版本号常量变更**。
这是管线正确性的强校准。

## 3. 差分的量化现状

| 指标 | E-M5 v2.2 → v2.3 |
|---|---|
| 块 0 变化字节 | 3,319,143（23.45%） |
| 字符串锚点对齐后残差 | 155,296（**21× 改善**），49,253 跨度，分布于 671/3,456 页 |
| 归一化后函数指纹完全相同 | 28,285/54,843（51.6%，v2 遮蔽规则）/ 45,067（82.1%，v1 规则） |
| 地址指纹相同但代码不同的函数组 | 135 组 |
| 比较常量频次变化的常量 | 约 40 个（多为重构噪声） |

**问题所在**：三年期固件间隔导致**大量函数的寄存器分配与代码形态改变**，
真正的小补丁淹没在 ~9,800 个变化的函数里。
字节级差分与函数级差分都需要更强的锚点。

## 4. 下一步：确切的做法

### 4.1 首选 —— 拿到「更近」的基线（把噪声比降到最低）

噪声主要来自三年期的重编译。若能拿到**紧邻 v2.3 的修复前版本**，差分会干净得多。

xdel.ru 已提供 E-M5 v2.0/v2.1/v2.2 与 E-PM2 v1.1–v1.5；
**E-PM2 v1.5 → v1.6 只有约 2 年间隔**，噪声应显著低于 E-M5 的 3 年。
⇒ **先对 E-PM2 v1.5/v1.6 跑同一套语义差分**，若能自动找出版本号常量
（`0x1501 → 0x1600`）并把残差降到几百个字节，补丁就会浮出来。

> 预期校准：E-PM2 的版本常量应为 `0x1501` → `0x1600`。
> 找到它即证明管线在该对上同样有效。

### 4.2 次选 —— 用「同一对」的交叉验证缩小候选

对 E-M5 与 E-PM2 两组**都**成立的候选（同一功能在两个机型都被改）才是松下修复。
语义差分已经能给出每组的候选函数列表，取交集即可。

### 4.3 第三条 —— 直接追「每镜头 AF 参数组」

报告 §5.2 记录块 0 内有 **12 个命名数组 + `af_data_pos[%d]`**；
cmdada `notes/autofocus.md` 描述机身侧约 **12 组每镜头 AF 参数块**
（`fcs_act_mode, ap_target, ap_speed, wob_amp, wob_move, ofs_time, ofs_move,
iaf_target, iaf_speed, iaf_dist`）。
若修复是"新增一个松下镜头组"，则这些数组会多一项或内容变化。

定位方法：在 Ghidra 里找出打印这 12 个数组名与 `af_data_pos[]` 的那个调试函数，
从它取出的**数组地址**反查数组本体；再在 v2.2 / v2.3 之间比对这些数组的内容。
（注意：数组是**数据**，不受代码重编译影响，地址可能稳定 ⇒ 差分噪声低。）

### 4.4 第四条 —— 块 0 里的「指针表」没有

`tools/find_ptr_tables.py` 在块 0 里找不到「连续指向块 0 的指针数组」
（唯一命中是 `0x90909090` 填充模式的假阳性）。
⇒ AF 参数数组不是用指针表索引的，可能用偏移表或结构体内联。

## 5. 对「新增创意滤镜 / 解锁功能」目标的现状

| 目标 | 现状 | 还差什么 |
|---|---|---|
| 滤镜实现位置 | ✅ 已确认在块 0（`art_*` 子系统，效果 ID 10/20/30/40/50，多 pass 管线） | 效果注册表（ID → 处理函数/参数块）的确切地址 |
| 滤镜 UI 名字位置 | ✅ 已确认在块 1（UTF-16LE 字符串池，资源 ID A03F–A048） | "资源 ID → 效果 ID"的对应表；块 1 内可复用的空白区（大小固定） |
| 解锁门控位置 | ✅ 已知门控函数存在（`art_chk_type_rec` / `art_chk_type_mov` / `art_IsSupportType` / `art_chk_effect`） | 这些函数的**地址**；由于 `art_*` 名字无引用，只能靠数值/行为反推 |
| 解锁的字节形态 | ✅ 社区先例已提取（3 个通用模式，全部只落块 0） | 把先例映射到 E-P5 的具体偏移 |
| 补丁重打包 | ✅ `replace_payload()` 可改 payload 并重算 sum32 | 实机刷写验证 |

**一个关键未知（诚实边界）**：`art_*` 是**残留的符号名表**（Ghidra 全量验证 0 引用），
因此**无法用名字直接定位滤镜代码**。
唯一的可行路径是**数值反推**：例如"比较效果 ID 10/20/30/40/50 的函数"
（Ghidra 已给出 3 个候选：`FUN_4047975c` / `FUN_4048b6d2` / `FUN_4049893c`），
再用"引用了增益图数据的函数"交叉确认。
