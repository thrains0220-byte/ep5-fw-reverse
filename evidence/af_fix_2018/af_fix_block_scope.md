|---|---|---|---|---|

⇒ **2018-12-18 的松下镜头 AF 修复完全落在块 0（MN103 主代码块）**，
块 1（多语言+字体）、块 2（6-bit 编码区）、块 3（文字叠加位图）**一个字节都没动**。

> **对"新增创意滤镜"目标的直接含义**：
> 滤镜的**实现**在块 0（已确认），但滤镜的**UI 名字**在块 1。
> ⇒ 新增滤镜需要**同时**改块 0 与块 1；而 AF 修复这类纯行为修复只改块 0。
> 块 1 各机型大小固定（如 E-P5 22,937,536 B），新增名字需要找到可复用的空白区
> 或确认字符串池允许变长。

## 3. 字节级差分为何不可用：整包重编译

E-M5 v2.2 → v2.3 的块 0 **长度完全相同**，但 23.45% 字节不同、349,129 个跨度。
⇒ 三年间代码被整体重编译并重排，逐字节差分无法定位补丁。

### 3.1 字符串锚点对齐（`tools/align_diff.py`）

用两版之间**内容不变**的可打印字符串作锚点反推位移：

| 位移 | 覆盖量 |
|---|---|
| `+0` | 3,168 KB |
| `+664` | 732 KB |
| `+704` | 688 KB |
| `+12` | 380 KB |
| 其他 | 逐页细分 |

对齐后残差：**3,319,143 → 155,296 字节**（21× 改善），49,253 个跨度。
残差在 671/3,456 页上分布 —— 说明**大量函数的寄存器分配/代码形态在三年间改变**，
残差以"分支位移重定位"为主，不是语义改动。

### 3.2 版本间字符串增减（`tools/str_delta.py`）

| 项 | 数量 |
|---|---|
| 修复前唯一串（≥6 字符） | 42,861 |
| 修复后唯一串 | 42,865 |
| 只在修复前出现 | 206 |
| 只在修复后出现 | 210 |
| **其中有意义的新增标识符** | **0** |
| **其中有意义的消失标识符** | **0** |

⇒ **AF 修复没有引入任何新的命名符号/字符串**。
它是纯粹的既有代码行为改动（新增分支或改写常量），不新增可见的功能名。

## 4. 语义级差分（Ghidra 归一化函数集合）

借助新装的 MN10300 Ghidra 模块，把块 0 导入 Ghidra 并做全量线性反汇编 + 建函数，
再把每个函数导出为**归一化反汇编**（`tools/ghidra/Mn103DumpNormalized2.java`）：

归一化规则：
- 分支/调用目标 → `T`（重定位噪声）
- 指向**镜像自身**的地址 → `A`（代码/数据重排噪声）
- **RAM 全局 (0x60xxxxxx) 与 mask ROM (0x7Exxxxxx) 原样保留**
  —— 这两类地址在两版之间稳定，且能标识功能（AF/镜头函数会引用它们）

| 项 | E-M5 v2.2 | E-M5 v2.3 |
|---|---|---|
| 识别函数数 | 54,843 | 54,864 |
| 归一化指纹**完全相同**的函数 | — | **45,067**（82.1%） |
| 仅修复前出现 | 9,776 | — |
| 仅修复后出现 | — | 9,797 |

⇒ 代码形态在三年间确实大改（仅 18% 函数指纹不变），
但这 45,067 个相同函数构成稳定基座，**改动最少的配对即补丁候选**。

配套脚本：`tools/semdiff.py`（多重集合差）、`tools/semdiff2.py`
（用 difflib 对差集做最优配对，按改动 token 数升序列出，并标注是否触碰 RAM/ROM）。

## 5. 由此得到的方法论（供后续复用）

| 经验 | 说明 |
|---|---|
| 奥林巴斯固件的块内字符串**不能靠立即数寻址** | 块 0 的 62,167 条字符串里只有 1 条被 `fc <imm32>` 直接寻址 |
| `art_*` 是**残留符号名表** | Ghidra 全量验证：0 引用。只能当"词汇表"，不能当"定位符" |
| 版本差分必须**先对齐再比** | 字节级差分对三年期固件无效；字符串锚点对齐 + 语义归一化才有效 |
| **块 1/2/3 逐字节相同**是极强的收窄信号 | 一旦确认，修复必然在块 0 的代码里，不在数据/字体/加密区 |
