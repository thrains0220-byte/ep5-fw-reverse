## 1. 补丁点（字节级）

### 1.1 E1 —— 菜单类型码（1 字节）

运行地址 `0x40573298`（payload 偏移 `0x2B3298`）：

```
0x40573296  f0 04        MOV (A0),A1
0x40573298  80 04        MOV 0x4,D0          ← 改成 80 00
0x4057329A  f8 51 6b     MOVBU D0,(0x6b,A1)   ; *(u8*)(A1+0x6B) = 4  →  0
```

【观察】该类型码是第 14 轮定位的「录像侧菜单描述符选择点」：
9 个写入点里只有它会选到 `0x7E452BE4`（录像 4 项那张），其余 8 个都落到 `0x7E452BDC`（照片 10 项那张）。
⇒ 把它改成 `0` ⇒ 录像形态改读**照片那张 10 项描述符**。

【验证】模式 `80 04 f8 51 6b` 在块 0 **只命中 1 处**（`0x40573298`）⇒ 改这一处不会误伤。

### 1.2 E2 —— 20 槽参数块表（40 字节）

运行地址 `0x40A56338`（payload 偏移 `0x796338`），20 × u32：

```
槽 0..9  （照片侧）: 0x7E5C9171 0x7E5C9194 0x7E5C913E 0x7E5C918F 0x7E5C9194
                       0x7E5C9194 0x7E5C9194 0x7E5C9169 0x7E5C9194
槽 10..19（录像侧）: 0x7E5C9194 0x7E5C9142 0x7E5C9185 0x7E5C9194 0x7E5C9194
                       0x7E5C9146 0x7E5C9194 0x7E5C9194 0x7E5C918A 0x7E5C916D
```

【观察】照片侧 10 槽只有 **4 个**指向非默认记录；录像侧 10 槽有 **5 个**。
【推断】把槽 10..19 的值整体换成槽 0..9 的值 ⇒ **录像形态改用照片形态的参数记录**。
【未知】槽位是否真的按「照片 0–9 / 录像 10–19」索引（第 12 轮的推断，未直接实证）——
**E2 若无效，说明索引方式不同，需要重新定位；但它不破坏任何东西。**

## 2. 拍照 / 录像 参数装载的分野（反编译实证）

`FUN_40788616(t)`（艺术簇 `0x40788616`）：

```c
uint FUN_40788616(uint t) {
  if (t & uRam602aeb94) {              // 0x602AEB94 = 类型支持位掩码
     if (t == 2) sVar1 = FUN_407868fc(0x605fca00, 0x7e5c9809, 0);   // 拍照参数源
     else { uRam605fccc4 = 0x7e5c9b1c;
             sVar1 = FUN_407bc0be(0x605fccc4, 0x7e8973d0, 0); }    // 录像参数源
  }
}
```

`FUN_4078866A(t)`（star_light 专用）结构相同：
`t == 2` → `FUN_40786937(0x605fca00, 2, t & 0x602AEB94, 0)`；否则 → `FUN_407bc102(0x605fccc4)`。

⇒ **`t == 2` = 拍照形态，`t == 1` = 录像形态**（第 14 轮结论，本轮再次实证）。
⇒ 录像侧的**参数源**在 `0x7E8973D0`，与照片侧的 `0x7E5C9809` 是**两个不同的 ROM 地址**，
所以「录像也用照片参数」不能只靠改类型码，**E2（槽表改指）正是补这一刀的地方**。

模式唯一性已验证；相机若拒绝就仍跑 v1.8。

### 建议测试顺序

1. **先刷 C1**（1 字节，风险最低）→ 看录像模式艺术滤镜菜单是不是 10 项。
   - 若**是** ⇒ 菜单解锁成功，下一步刷 C3 补参数。
   - 若**否** ⇒ 类型码 0 不指向照片描述符，需要换别的值（可试 1/2/3，1 字节，随便试）。

## 4. 这一轮同时确定的事

| 结论 | 证据 |
|---|---|
| **滤镜算法在 mask ROM，不在块 0** | 块 0 内指向艺术簇 `0x40788300–0x40789600` 的 u32 指针**只有 1 处**；`art_*` 只是名字串 |
| **块 0 的字符串完全不被块 0 代码引用** | u32 立即数 / `fc dc`+u32 / 高低半字对 / u24 / PC 相对位移 / Ghidra 原生 xref —— **六种方式全部 0 命中**（连 `DCOLYMP`、`E108????BIN`、`art_white_edge_pass_err` 都是 0） |
| ⇒ 字符串是**给人看的**，绑定靠**编号表** | `sxN` / `sxN/` / `**函数名()*` 三连（第 20 轮的 AF 机制），全块只有 AF 模块有具名表 |
| 后果 | 「跨子系统的代码↔字符串导航」暂时不可得 ⇒ R-5（限制常量分诊）只能靠**逐段反编译**，不能按名字检索 |
