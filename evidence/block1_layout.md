# 块 1（多语言 UI 资源块）内部布局

> 日期：2026-10-22（第十三轮）
> 目的：为"往块 1 增加新滤镜名字 / 改菜单"确定**可操作空间**。
> 性质：静态观察。

---

## 0. 结论

**块 1 = 一张 70 项的 `(ptr, size)` 资源表 + 70 个紧密排列的数据分区，零间隙。**

⇒ **块 1 不能加长**（大小固定 22,937,536 B），
新增一个菜单项字符串**必须用「等长替换」**：
在某个语言分区的已有 UTF-16 字符串上原位替换，保持字节长度不变。

---

## 1. 头部资源表

块 1 偏移 `0x000` 起，每 **16 字节**一条记录 `{u32 ptr, u32 size, u32 pad}`：

```
0x00000000  00 08 7C 42  00 36 2B 00  00 00 00 00   -> 0x427C0800  0x2B3600
0x00000010  00 3E A7 42  00 A2 01 00  00 00 00 00   -> 0x42A73E00  0x0001A2
0x00000020  00 E0 A8 42  00 D2 00 00  00 00 00 00   -> 0x42A8E000  0x0000D2
0x00000030  00 B2 A9 42  00 D2 00 00  00 00 00 00   -> 0x42A9B200  0x0000D2
0x00000040  00 84 AA 42  00 8A 01 00  00 00 00 00   -> 0x42AA8400  0x00018A
0x00000050  00 0E AC 42  00 86 01 00  00 00 00 00   -> 0x42AC0E00  0x000186
0x00000060  00 94 AD 42  00 A4 01 00  00 00 00 00   -> 0x42AD9400  0x0001A4
0x00000070  00 38 AF 42  00 B2 01 00  00 00 00 00   -> 0x42AF3800  0x0001B2
```

**共 70 条记录**（表本身占 `0x000..0x470`）。

### 1.1 分区类型

| 记录 | 地址 | 大小 | 推断 |
|---|---|---|---|
| **#0** | `0x427C0800` | **2,831,872 (2.7 MB)** | **主文本池**（所有语言共用的字符串库） |
| #1 | `0x42A73E00` | 107,008 | 字体/图形资源 |
| #2–#4 | `0x42A8E000`… | 53,760 / 53,760 / 100,864 | 字体 |
| #5–#34 | `0x42AC0E00`… | 72,192–117,760（均为 `0x1A000`=106,496 的整数倍附近） | **各语言文本分区**（每个约 100–117 KB，按 0x4000 对齐） |
| #35–#70 | `0x42DB8000`… | 13,824–312,832 | 更多字体/图形/小分区 |

**对齐规律**：各分区大小均为 **0x4000（16 KB）的整数倍**；
每个分区的起始地址也落在 0x4000 边界上。

### 1.2 间隙统计

**70 条记录，两两之间的 gap 全部为 0**（含最后一条到块尾）。

⇒ **块 1 完全紧凑，没有任何可借用的空白区。**

## 2. 对「新增滤镜名字」的可操作性结论

| 方案 | 可行性 | 说明 |
|---|---|---|
| 在分区尾部追加新字符串 | ❌ | 无空白；追加会顶到下一分区 |
| 修改头部表项指向新位置 | ❌ | 无处可放新数据 |
| **等长替换已有字符串** | ✅ | 用相同 UTF-16 字节长度替换某个不用的名字，菜单项内容即变 |
| 借用**块 0** 空间 | ⚠️ | 块 0 与块 1 是独立块，字符串池在块 1 内，跨块取不到 |

**⇒ 最现实的做法**：
1. 在块 1 找到一个**已存在但未在照片模式菜单使用**的名字槽位
   （例如 `Star Light` @ `0x33B7C0` / `White Edge` @ `0x355B42` / `Pastel` @ `0x2E92DC` —— 这三个
   **名字已存在但无菜单 ID**！）；
2. 给它分配空闲资源 ID **`A04F`**；
3. 在**照片模式菜单的资源 ID 列表**（`0x40E2F73E` 的 `[A03F..A048]`）里加一项 ——
   该表在**块 0**，可加长（块 0 长度固定 15,728,576 B，但同样无空白 ⇒ 需等长替换或改用别的机制）；
4. 在**图像引擎 20 槽 ROM 表**（`0x40A56338`）里给它一个槽位。

> **关键约束提示**：步骤 3、4 涉及的表都在**块 0**，
> 而块 0 也是固定长度、无空白 ⇒ 这两张表同样只能**等长替换**或**利用表内的重复项**。
> 例如 T1 表尾已有值 `50`（= 效果 ID 50 = white_edge），
> 说明该表**本来就带一个效果 ID 字段** ⇒ 结构可能是
> `[菜单ID×10][某效果ID]`，新增一项需要腾出空间。

## 3. 主文本池（记录 #0）内部

- 范围：`0x427C0800 .. 0x42A73E00`（2,831,872 B）
- 内容：全部语言的 UTF-16 字符串（每条 NUL 结束）
- 池内零填充段：见 `tools/block1_manifest.py` 输出（≥64 B 的零段）
- **可利用空间**：池内若存在零填充段，可在其中放置新字符串（UTF-16 NUL 结束），
  并把菜单项指向它 —— 这是**唯一不需要等长替换**的加名途径。

---

## 4. 复现

```sh
python tools/block1_manifest.py        # (ptr,size) 表 + 间隙 + 零填充段
python tools/block1_layout.py           # 区域类型 + 语言分区密度 + 对齐统计
```
