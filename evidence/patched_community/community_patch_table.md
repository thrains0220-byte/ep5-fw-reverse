# 社区"改机"归档的字节级补丁表（奥林巴斯解锁功能的真实形态）

> 日期：2026-10-22
> 数据源：xdel.ru `original/` 与 `patched/` 目录
> 方法：解包 → 用本项目 `tools/oly_container.py` 解混淆 → 与对应**原版**固件逐字节差分
> 性质：**观察（静态）**。社区补丁的功能效果来自社区描述，本表只证明**字节差异**。

---

## 0. 为什么这张表重要

用户目标之一是"**解锁被锁住的功能**"。奥林巴斯没有公开过这些开关的位置，
但社区改机归档**直接把答案写在了字节里**：他们改的就是**门控判定的那几条指令**。
把这张表读懂，就等于拿到了"解锁"在固件层面的**可复用模板**。

本表同时是本项目差分管线的**正确性验证**：E-M5 II v4.1 补丁算出的
decoded 偏移 `0x3F2AD5 / 0x534866 / 0x53486C`，与 fishcu/oly_fw_analysis
独立记录的 `0x3f2ad5 / 0x534866 / 0x53486c` **逐字节吻合**。

## 2. 三个通用模式

### 模式 A —— 12 字节，"解除某项限制"（E-M1 II v3.4 / E-M1 III v1.2 / E-M5 III v1.4）

```
stock  : 1c a0 06 c8 14 a0 03 c8 10 a0 08 c8
patched: fc cc 10 00 00 70 60 88 1c df 80 1c
```

三个机型**字节完全相同** ⇒ 这是同一段源码的同一处改动，被链接进多个机型。
原序列可解读为「一系列短比较 + 条件跳转」（`a0` = `cmp imm8,d0`，
`c8` = `beq`，`14/03/10/08` = 比较值），补丁序列则把它换成一组不同形态的指令。

| 机型 | decoded 偏移 | flash 地址 | .BIN 文件偏移 |
|---|---|---|---|
| E-M1 II v3.4 | `0x33399F..0x3339AA` | `0x4089399F` | `0x3339BF` |
| E-M1 III v1.2 | `0x3232ED..0x3232F8` | `0x40B232ED` | `0x32330E` |
| E-M5 III v1.4 | `0x316B1C..0x316B27` | `0x40A96B1C` | `0x316B3D` |

> E-M1 III v1.5 的社区文字配方（`e-m1-iii-v15.txt`）在同一区域给出
> `.BIN` 文件偏移 `0x32330F` 等 —— 偏移体系一致（仅版本不同导致 1 字节位移）。

### 模式 B —— 2 字节，"跳过一处判定"（E-M5 II v4.1 / E-M1 II v3.4 / E-M1 III v1.2 / E-M5 III v1.4）

```

patched: cb cb

```

```
0x3339B3: 09        -> 04
0x3339B6: 2c        -> fc
0x3339B8: 06 ca 05 2c 20 1c  ->  70 70 70 70 cb cb
0x635A2A: c9 04     -> cb cb
```

## 3. 偏移体系说明（重要）

本表给出**三种偏移**，互不等价：

| 体系 | 含义 | 用途 |
|---|---|---|
| `decoded` | 解混淆后块 0 内的偏移 | 反汇编定位（Ghidra / objdump 用这个） |
| `flash` | 运行时地址（块 0 装载地址 + decoded 偏移） | 与 fishcu 文档、各类 wiki 的地址一致 |
| `.BIN 文件偏移` | 原始固件文件内偏移（已计入 16 列置换） | 直接 `fc /b` 打补丁用；与社区文字配方格式一致 |

置换关系（来自 `tools/oly_container.py` 的 `DECODE_ORDER`）：
`raw = block_payload_start + DECODE_ORDER[off % 16] + 16 * (off // 16)`。

---

## 4. 对本项目目标的意义

1. **"解锁功能"的字节形态已知**：社区改机就是改块 0 里 2~14 字节的门控判定。
   本项目若要解锁 E-P5 的某个功能，需要做的是**同一种手术**：
   找到对应判定 → 改 2 字节 → 重算 sum32 → 重新打包 → 刷机。
2. **模式 B / C 在多个机型上复现** ⇒ 它们对应的是**跨机型通用的判定**
   （很可能是"此功能在本机型是否支持"一类的机型/地区门控）。
3. **模式 A 在三个机型上完全一致** ⇒ 同一段通用逻辑。
4. 这些补丁**全部不在块 1/2/3**，因此"改块 0 的代码 + 重算校验和"是完整可行的路径。
