# 艺术滤镜在 `.BIN` 内的可见性边界 —— 逐滤镜「被锁清单」为何做不出来

> 日期：2026-10-23（第二十轮）
> 基线：E-P5 v1.8 块 0（`0x402C0000`，Ghidra 工程 `mn103_full`）
> 工具：`tools/ghidra/Mn103FindArtTypeInit.java`、`tools/str_refs.py`、
> `tools/find_str_base.py`、`tools/find_bytes.py`、`tools/rom_addr_neighborhood.py`
> 性质：**观察（静态）**。

---

## 0. 结论

> **E-P5 的 `.BIN` 里，块 0 只能看见艺术滤镜的「公共框架」，
> 看不见「逐滤镜的拍照/录像初始化」。**
>
> ⇒ 第十四轮路线图里的 P0「逐个检查 13 个滤镜模块的初始化函数 → 产出被锁清单」
> **在 `.BIN` 层面不可完成**（不是没做，是做不出来）——
> 原因是**分派表、模块入口、名字指针、逐滤镜初始化参数，全部在机身 mask ROM**。
>
> ⇒ 目标②在 `.BIN` 层面**最终只剩一个可操作点**：
> **`FUN_407731F7` 里的类型码 1 字节**（决定用哪一张 mask ROM 菜单描述符）。

---

## 1. 四项可见性检验

### 1.1 艺术滤镜的**字符串**在块 0 内零引用

| 检验 | 结果 |
|---|---|
| 4 字节地址引用（`str_refs.py`，含 `fc` 前缀判定） | **0** |
| 指针表条目（`find_bytes.py` 搜 `f4 4e 71 40` = `0x40714EF4`） | **0** |
| 承载它们的基址寄存器（`find_str_base.py` 扫 `0x40710000`–`0x4071C000` 的 `fc dc <imm32>`） | **0 个** |

⇒ 既不是立即数寻址，也不是指针表，也不是「基址 + 16 位位移」。
⇒ **这些字符串只能被 mask ROM 侧的代码/数据引用**
（`.BIN` 的装载地址是固定的，ROM 里持有指向它们的指针是可能的）。

### 1.2 「子 ID → 处理函数」分派表在 mask ROM

`FUN_40788DEE` 里的间接跳转：

```c
if (*(uint32 *)(iVar6 + 0x7e897cf4) == uVar8) {
    UNRECOVERED_JUMPTABLE = *(code **)(iVar6 + 0x7e897cf8);
    (*UNRECOVERED_JUMPTABLE)(...);        /* ← 从 mask ROM 取函数指针并调用 */
}
```

`0x7E897CF4` = 16 槽 × 8 字节（`{ID, 处理函数指针}`），按 `id & 0x0F` 索引。
⇒ **哪个滤镜 ID 对应哪个实现，由 mask ROM 决定。**

### 1.3 拍照 / 录像参数装载**只有 2 个调用者**

| 参数装载函数 | 语义 | 调用者 | 引用处 |
|---|---|---|---|
| `FUN_407868FC` | 拍照参数（→ `0x605FCA00`，源 `0x7E5C9809`） | `FUN_40788616`（通用按类型初始化） | `0x40788631` |
| `FUN_407BC0BE` | 录像参数（→ `0x605FCCC4`，源 `0x7E8973D0`） | `FUN_40788616` | `0x40788656` |
| `FUN_40786937` | star_light 专用拍照版 | `FUN_4078866A` | `0x4078867F` |
| `FUN_407BC102` | star_light 专用录像版 | `FUN_4078866A` | `0x4078868C` |

而 `FUN_40788616` / `FUN_4078866A` 自身**各只有 2 个调用者**：

| 函数 | 调用者 | 语义 |
|---|---|---|
| `FUN_40788616` | `FUN_407883DD`（子系统总初始化）×2 | `t = 1` 与 `t = 2` 各一次 |
| `FUN_4078866A` | `FUN_4078846D`（star_light 初始化）×2 | `t = 2` 与 `t = 1` 各一次 |

⇒ **块 0 内为「某个滤镜装载拍照/录像参数」的代码路径只有 2 条，且都是按类型统一处理**，
**没有 13 个滤镜各自的初始化函数**。

⇒ **「逐滤镜判定录像形态是否被初始化」这个命题，在 `.BIN` 内没有可观测的落点。**

### 1.4 mask ROM 里的菜单描述符表：4 字节步长、连续 52 项

`rom_addr_neighborhood.py` 在 `0x7E452B30`–`0x7E452BFC` 窗口内找到 **76 个被引用的 ROM 地址**，
其中 `0x7E452B30` → `0x7E452BE4` 一段是**严格 4 字节步长、每个各被引用 1 次**的连续族，
且**全部引用点集中在块 0 的 `0x403E7B00`–`0x403E7E00`**（= 第十四轮定位的
6 个平行描述符选择函数所在区）。

| 描述符选择函数 | 引用到的 mask ROM 地址 |
|---|---|
| `FUN_403E7B1B` | `0x7E452B30`(默认) / `B40`(码2) / `B48`(码4) / `B50`(码5) / `B58`(码6) |
| `FUN_403E7B79` | `0x7E452B34` / `B44` / `B4C` / `B54` / `B5C` |
| `FUN_403E7C3F` | `0x7E452B60` / `B68` / `B6C` / `B70` / `B74` |
| `FUN_403E7E94` | `0x7E452BDC` / `BE4` / `BEC` / `BF4` / `BFC` |

⇒ **每个菜单描述符只有 4 字节**（很可能是 `{u16 首资源ID, u16 项数}` 或 `{u16 项数, u16 首资源ID}`）。
⇒ **「照片 10 项 / 录像 4 项」这两个数字，就写在这两个 4 字节的 mask ROM 结构里。**
⇒ **判定只需读 mask ROM 的 8 个字节** —— 这把「需要 mask ROM」的必要性
从「拿到 13 MB 映像」压缩到「拿到 8 个字节」。

## 2. 由此得到的最终可操作集

| 想做的事 | `.BIN` 内可行？ | 落点 |
|---|---|---|
| 逐滤镜判定「录像形态被锁」 | ❌ | 分派表 / 初始化参数在 mask ROM，块 0 内不可见 |
| 给某个滤镜加专属初始化 | ❌ | 同上 |
| 新增菜单项 | ❌ | 菜单描述符（4 B）在 mask ROM |
| 改菜单项显示文字 | ✅ | 块 1，等长替换 |
| **换用另一张菜单描述符** | ✅ | **`FUN_407731F7` 的 `+0x6B = 4` → `0`（1 字节）** |
| 改「用哪一组 ROM 参数」 | ✅ | 1 个 4 字节立即数（`mov <ROM>,a0`） |

⇒ **`.BIN` 层面能给艺术滤镜做的，只有「换一张 mask ROM 里已有的清单」这一类操作。**

---

## 3. 下一步的两条判定路径

### 路径 A（需 8 字节的 mask ROM 读）：直接读描述符

读 `0x7E452BDC` 与 `0x7E452BE4` 各 4 字节：
- 若 `0x7E452BDC` = {首 ID=`A03F`, 数=10}、`0x7E452BE4` = {首 ID=`A042`, 数=4}
  ⇒ **把录像的类型码从 2 改成 0，录像菜单就直接读 10 项那张清单**（1 字节补丁成立）。
- 若两张各自独立 ⇒ ROM 里没有 10 项的录像清单可借，
  只能改 ROM 侧（本项目无写权限）。

### 路径 B（不需 mask ROM）：找「官方另有下发通道」

第十七轮已排除 `.BIN` 内含 ROM 映像；第十八轮全量普查再次确认。
⇒ 只剩：官方另发的 ROM 文件、机身服务工具、或实机 dump。

### 路径 C（新增，纯本地可做）：**给 E-P5 补一份「10 项录像清单」的等价物**

若路径 A 判定为"不可借"，那么 `.BIN` 侧唯一还能做的是——
**把录像菜单的条目清单从 mask ROM 改到块 0**（例如在块 0 里放一张 10 项的资源 ID 数组，
并把描述符选择函数改成返回它）。但描述符本身在 ROM ⇒ 仍需 ROM 侧配合。
⇒ 路径 C 的前提还是路径 A/B。

## 4. 复现

```sh
# 描述符表形状（4 字节步长、引用簇）
python tools/rom_addr_neighborhood.py --blk0 decoded/00_0100_402c0020.decoded.bin \
    --center 0x7E452BDC --span 0x120

# 参数装载函数的调用者普查
fw-work/ghidra-mn103/artpi.bat          # -> out/artparaminit.txt
# 类型初始化函数的调用者普查
fw-work/ghidra-mn103/artti.bat          # -> out/arttypeinit.txt

# 字符串可见性检验
python tools/str_refs.py --blk decoded/00_0100_402c0020.decoded.bin --names art_effect_10_star_light
python tools/find_str_base.py --blk decoded/00_0100_402c0020.decoded.bin --lo 0x40710000 --hi 0x4071C000
```
