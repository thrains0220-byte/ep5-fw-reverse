# E-P5 1.8 艺术滤镜「录像形态」落点 —— 精确定位（2026-10-22 第九轮）

> 方法：Ghidra + MN10300 SLEIGH + 反编译伪代码 + 全局引用图
> 性质：**静态观察**。所有地址同时给出 **运行时地址** 与 **块 0 文件内偏移**（可直接打补丁）。

---

## 1. 决定性观察：拍照参数区与录像参数区的引用数不对等

| 参数区 | 地址 | 引用它的代码位置 | 引用数 |
|---|---|---|---|
| **拍照**参数区 | `0x605FCA00` | `0x40788572` (FUN_40788562)、`0x40788624` (FUN_40788616)、`0x40788679` (FUN_4078866A)、**`0x40788A5E`**（无函数名） | **4** |
| **录像**参数区 | `0x605FCCC4` | `0x4078857F` (FUN_40788562)、`0x40788643`/`0x40788649` (FUN_40788616)、`0x40788686` (FUN_4078866A) | **3** |

**⇒ 多出来的那一处（`0x40788A5E`）只绑定拍照参数区，没有任何录像分支。**

---

## 2. 该处的完整上下文（反汇编 + 伪代码）

`0x40788978` 起的**模式分派器**：

```asm
0x40788978  9F 08 F1 73        MOV 0x8,A3
0x4078897A  F0 07 71 A0        ADD A0,A3
0x4078897C  01 C8 10 FC        MOV (A3),A1
0x4078897E  C8 00 00 00 80     MOV (A1),D0
0x4078897F  C9 05 CC AE 00     CMP 0x1,D0            ; 模式 == 1 ?
0x40788981  CC CD 00 80 43     BEQ 0x40788991
0x40788983  CD 19 03 00 04     CMP -0x80000000,D0    ; 模式 == 0x80000000 ?
0x40788989  73 90 08 F1        BNE 0x4078898e
0x4078898B  60 00 85 08        JMP 0x40788a39        ; → 分支 B
0x4078898E  DD 80 3D 03        JMP 0x40788a5b        ; → 分支 C（只有拍照）
0x40788991  73 90 08 F1 60 00  MOV 0x43,D0
0x40788993  85 08 DD 80 3D 03  CALL 0x40788cac       ; → 分支 A
```

分支 C（**只有拍照**）：

```asm
0x40788A5B  40 05              MOVBU (0x5 ,A0),D0
0x40788A5E  FC DC 00 CA 5F 60  MOV 0x605fca00,A0    ; ← 只加载【拍照】参数区
0x40788A64  CD A0 DC B0 14     CALL 0x40786704
0x40788A69  DF F0 14           RET [A3,A2,D3,D2],0x14
```

分支 B（另一套状态结构，不走参数区）：

```asm
0x40788A39  EA 2A 60          MOV D0,(0x602aea1c)
0x40788A3F  FC A1 E8 C9 5F 60  MOV (0x605fc9e8),A1
0x40788A45  F1 EC FC 84 44     MOV D3,A0
0x40788A47  EB 2A 60          MOV A1,(0x602aeb44)
0x40788A4D  FC DD 1C EA 2A 60  MOV 0x602aea1c,A1
0x40788A53  CD 3B E0 F0 1C     CALL 0x40786a8e,[D2,D3,A2,A3],0x1c
```

## 3. 精确补丁位置（可直接用）

| 项 | 值 |
|---|---|
| **运行时地址** | `0x40788A5E` |
| **块 0 文件内偏移** | `0x004C8A5E` |
| 当前字节（6 字节） | `FC DC 00 CA 5F 60` = `mov 0x605FCA00,a0`（拍照参数区） |
| 录像参数区常量 | `0x605FCCC4` → `FC DC C4 CC 5F 60` |

**⚠️ 诚实的限定**：把 `0x605FCA00` 直接改成 `0x605FCCC4` **不等于**"解锁"——
`0x40788978` 的分派是按对象里的**模式字段**（`*(obj+8)`）三分支，
录像路径走的是分支 B（`0x602AEA1C` / `0x602AEB44` 状态结构），
而不是"把拍照参数区换成录像参数区"。

⇒ **正确的解锁改法是补一条录像分支**，而不是替换常量。
具体改法需要先确定：
1. 模式字段的取值域（`1` / `0x80000000` / 其它 分别代表什么），
2. 录像形态下应当加载的参数区与调用序列（可参照 `FUN_40788616` 的 else 分支：
   `uRam605fccc4 = 0x7e5c9b1c; FUN_407bc0be(0x605fccc4, 0x7e8973d0, 0);`）。

## 4. 跨机型对照（**部分完成，遇到方法论障碍**）

**E-M5 II v4.1**（Olympus 在 v3.5/v4.0 官方解锁了电影艺术滤镜）应当有对应的录像分支。
**若 E-M5 II 的同一处代码存在录像分支，而 E-P5 没有 ⇒ 这就是厂商"解锁"的真实补丁形态。**

### 4.1 已完成的部分

| 步骤 | 状态 |
|---|---|
| E-M5 II v4.1 解混淆（21,364,672 B 块 0，往返一致） | ✅ |
| E-M5 II 块 0 导入 Ghidra + 全量反汇编（66,028 个 RAM 全局） | ✅ |
| E-M5 II 是否有 `art_effect_*` 名字表 | ❌ **没有**（命名体系不同） |
| E-M5 II 块 0 的 `art_*` 标识符 | 是 `art_Communication` / `art_Play_Sound` 等**无关**前缀 |

### 4.2 障碍：两机型的内存映射不同，**不能按地址直接对比**

| | E-P5 1.8 | E-M5 II v4.1 |
|---|---|---|
| 块 0 大小 | 15,728,576 B | 21,364,672 B |
| 0x60xxxxxx 引用数 | 15,236 | **66,028** |
| 0x7Exxxxxx 引用数 | **59,850** | **62** |
| 推断 | 0x60xxxxxx = RAM，0x7Exxxxxx = **mask ROM** | 0x60xxxxxx 同时承载 **ROM 数据**（0x60Axxxxx 一带高频出现） |

⇒ **E-M5 II 的 mask ROM 被映射到了与 E-P5 不同的地址区间**
（高频目标如 `0x60A092B0` / `0x60A418E5` / `0x60A56F25` 呈 ROM 数据特征），
所以「按 ROM 地址集合做差集」这条路**在两个机型之间不成立**。

### 4.3 正确的对照做法（下一轮执行）

**按结构找，而不是按地址找**：

1. 在 E-M5 II 块 0 中找**同款 312 字节拷贝循环**（`iVar4 = -0x4E` 的 do-while + 两次 `MOV` 指针递增）
   —— 这是艺术滤镜效果参数覆盖逻辑的**唯一指纹**；
2. 在其前后找**同样存在"只绑定一个参数区"的分派器**；
3. 对比两个机型的分派器结构，确认 E-M5 II 是否多出录像分支；
4. 把多出来的分支**移植**到 E-P5 的 `0x40788978` 附近。

> 这一步是本项目**最有价值的一次对照**，能把"猜测"变成"实证"。

## 5. 艺术效果 ID 空间的横向对照（已完成）

对 2012/2013 代全部已解码机型扫描 `art_effect_<ID>_<name>` 名字表：

| 机型 / 版本 | 效果 ID 空间 |
|---|---|
| E-P5 1.8 | `10 star_light, 20 pinhole, 30 frame, 40 soft_focus, 50 white_edge` |
| E-M5 v2.2（修复前） | 同上，**完全一致** |
| E-M5 v2.3（含修复） | 同上，**完全一致** |
| E-PM2 v1.6 | 同上，**完全一致** |
| E-M5 II v4.1（更新代） | **无 `art_effect_*` 名字表**（命名体系不同） |

⇒ **这 5 个效果就是 2012/2013 代平台的完整艺术效果集合**，
不存在"ROM 里还有第 6 个 art 效果但固件没暴露"的情况。
**"新增滤镜"因此只能走两条路**：
- **A. 解锁这 5 个效果的录像形态**（本文件 §1–§4，完全可行）
- **B. 从更新代机型移植效果实现**（E-M5 II 等，算法在 mask ROM，**需要实机 ROM dump**）
