# 艺术滤镜的每一份数据在哪、能不能用 `.BIN` 改 —— 判定表

> 日期：2026-10-23（第十八轮）
> 基线：E-P5 v1.8（块 0 `0x402C0020` / 块 1 `0x427C0020` / 块 2 `0x43DA0020` / 块 3 `0x44000020`）
> 交叉对照：E-M10 II v1.4、E-M5 v2.2/v2.3、E-PM2 v1.5/v1.6、E-M1 II/III、E-M5 II/III、
> E-M1 v4.6、E-PL9 v1.1、PEN-F v3.1（共 33 个已解码块 0）
> 性质：**观察（静态）**。不含执行 / 刷机证据。

---

## 0. 结论

> **E-P5 的艺术滤镜，「能改」的部分只有两处，其余全在机身 mask ROM：**
>
> | 改动 | 位置 | 代价 |
> |---|---|---|
> | ✅ 菜单项的**显示文字** | 块 1 | 等长替换（字节数必须不变） |
> | ✅ **「用哪一组 ROM 参数」的指针立即数** | 块 0（1 个 4 字节立即数） | 只能用 ROM 里**已有**的参数组 |
> | ❌ 新像素算法 | mask ROM | 需实机 / 官方渠道 |
> | ❌ 新调校参数组 | mask ROM | 同上 |
> | ❌ 新增菜单项本身 | mask ROM（菜单描述符） | 同上 |
> | ❌ 新的色调/对比度曲线 | E-P5 **四个块里都没有** | 同上 |
>
> ⇒ **「新增创意滤镜」在 E-P5 的 `.BIN` 层面没有可行解**；
> 可交付的极限是「**用 ROM 里已有的另一组参数做一个变体**」，
> 而这个变体**能不能出现在菜单里**仍取决于 mask ROM 的描述符。
>
> ⇒ **唯一能真正解锁的方向，是拿到机身 mask ROM 映像**（见 `docs/ROADMAP_NEXT.md` §1）。

---

## 1. 逐项证据

### 1.1 像素算法 / 菜单描述符 / 调校参数 → 全部在 mask ROM

| 项 | 地址 | 证据 |
|---|---|---|
| 效果参数源（拍照） | `0x7E5C9809` | `FUN_40788616` 伪代码 |
| 效果参数源（录像） | `0x7E8973D0` | 同上 |
| 滤镜分派表（子 ID → 处理函数，16 槽） | `0x7E897CF4` | `FUN_40788DEE` 里的 `mov <ROM>,a0` + 间接跳转 |
| 菜单描述符（10 项 / 4 项两份） | `0x7E452BDC` / `0x7E452BE4` | `FUN_403E7E94` 返回值 |
| 每镜头 AF 参数 | `LENS_INFO_LAF.af_data_pos[]` → ROM | 周边 6 张指针表全部指向 `0x7E1E`–`0x7E1F` |

**第十七轮已独立证明**：机身 `0x7Exxxxxx` 区段**不由 `.BIN` 承载、也不随固件更新下发**
（容器算术 / 块运行时地址 / 位移扫描 / 更新包与 MSRV 四项检验全部否定）。
**第十八轮在新机型上复核**（见 §1.4）—— 结论一致。

### 1.2 菜单显示文字 → 在块 1（✅ 可改）

- 块 1 是 UTF-16LE 多语言字符串池，22,937,536 B，头部 70 项 `(ptr, size)` 资源表，**零间隙**。
- 照片艺术菜单的资源 ID 段：`A03F`–`A048`（连续 10 项）；
  **录像艺术菜单只挂出 `A042`–`A045`（4 项）**，其余 6 项的字符串在池里**已经存在**。

### 1.3 块 1 资源分区内容分类（本轮新增，新工具 `tools/block1_resource_classify.py`）

对 70 项逐项做内容画像：

| 区段 | 内容 | 数量 |
|---|---|---|
| #0 | 主文本池（2,831,872 B，混排多语言） | 1 |
| #1–#34 | **UTF-16 语言分区**（每项 2,900–3,900 条字符串） | 34 |
| #35–#68 | **字体 / 图形**：可打印比 8–17%、熵 2.7–4.2、无 UTF-16 串 | 34 |
| #69 | 5,103,104 B 混合数据（打印 29.4%、熵 5.82） | 1 |

**关键词扫描（`art` / `filter` / `tone` / `lut` / `curve` / `gamma` / `color` / `sepia` / `mono` / `grain` / `effect` / `colortone` / `picture` / `expose`，大小写各一）⇒ 70 项全部 0 命中。**

⇒ **块 1 里没有艺术滤镜的 LUT / 曲线 / 预设表。**

### 1.4 新机型 `kind 0x106` 资源容器里的曲线表（新工具 `tools/blk106_resdir.py`）

第十六轮发现：新版机型（E-M1 v4.6 / E-M10 II / E-P7 / E-M1 II）的 `kind 0x106`
分区内部是一个**运行映像 + 40 条资源目录**。本轮把 E-M10 II v1.4 的这张目录完整解析：

- 目录位于 file `0x400`，**40 × 16 字节** `{运行地址, 大小, 0, 0}`；
- 覆盖运行地址 `0x43160800`–`0x4389DC00`（**7.4 MB**）；
- 结构呈**「图像 / 数据表」成对**：
  - 奇数号（如 #1/#3/#5/#7/#9）熵 6.6–7.6 ⇒ **JPEG**（魔数 `FF D8 FF E0` 在 **+32** 处，
    所以本轮顺手修正了第一版分类器「只认偏移 0 的魔数」的错误）；
  - 偶数号熵 3.0–5.6 ⇒ **数值表**；
- **#30–#39 是 10 个等长 41,472 B（0xA200）的 u16 色调曲线表**：
  32 B 零头 + 递增带平台的曲线（例如 #30：141,146,150,158,165,165,166,171,…,185→182→178 回落，
  呈**钟形**；#31：21,21,…,25,…,29 → 另一条上升曲线）；
  **#30 与 #32 内容完全相同**。

**三条关键的否定结论**：

1. 这些曲线表**在 E-M10 II 的块 0 里 0 处直接引用**，在 0x106 分区内的命中也只是
   目录项本身（file `0x5E0`/`0x5F0`/`0x600`）⇒ **经 mask ROM 间接寻址**。
2. 0x106 分区内**没有任何** `art_filter_` / `art_effect_` / `COLORTONE_` 字符串
   ⇒ 那里没有艺术滤镜代码，只有资源。
3. 0x106 内的**嵌套运行映像块地址只有** `0x43160400` / `0x43960000` / `0x43A60000`
   ⇒ **没有 `0x7Exxxxxx` 区段的映像**。
   ⇒ **新机型同样不随 `.BIN` 下发 mask ROM 映像**（第十七轮结论获跨代独立复核）。

### 1.5 决定性反证：E-P5 四个块里没有等价曲线

新工具 `tools/find_tone_curves.py`：取 E-M10 II v1.4 的 #30 曲线特征字节
（32 B 零头后的 64 B）到 E-P5 四个块里搜：

| 目标块 | 特征命中 | 曲线型候选 |
|---|---|---|
| 块 0 `0x402C0020`（15,728,576 B） | **0** | **0** |
| 块 1 `0x427C0020`（22,937,536 B） | **0** | **0** |
| 块 2 `0x43DA0020`（2,490,304 B，6-bit blob） | **0** | **0** |
| 块 3 `0x44000020`（3,669,952 B） | **0** | **0** |

⇒ **E-P5 的 `.BIN` 里既没有这张曲线，也没有同形态的曲线表。**

### 1.6 跨代修正：`art_filter_<HH>` 命名不是产品线通用

新工具 `tools/cross_model_art_map.py`（扫 33 个已解码块 0）：

| 机型族 | `art_effect_<NN>` / `art_filter_<HH>` 命名 | `COLORTONE_*` 名单 |
|---|---|---|
| **E-M5 v2.2 / v2.3、E-P5 v1.8、E-PM2 v1.5 / v1.6**（2012–2013 代） | ✅ 5 + 8 项 | 19–22 项 |
| E-M1 II v3.0/3.4/3.6、E-M1 III v1.2、E-M5 II v4.1、E-M5 III v1.4、E-M10 II v1.3/1.4、E-M10 III v1.2、E-M1 v4.6、E-PL9 v1.1、PEN-F v3.1（2014+ 代） | ❌ **0 项** | 23–25 项（E-M1 III 为 0） |

⇒ **修正第十四轮的推断**：
`art_effect_10` / `art_filter_06` 这套「ID 直接编进任务名」的编号体系
**只存在于 E-M5/E-P5 这一代**，**不是产品线通用约定**。
⇒ **「从别的机型搬一个滤镜实现过来」在 2014+ 机型上没有同名锚点可搬**，
跨代搬运的可行性因此大幅下降（第十四轮方向 2 的价值被这一条证伪）。

## 2. 由此得到的「.BIN 层可行集」

| 想做的事 | 能否在 E-P5 的 `.BIN` 里做到 | 理由 |
|---|---|---|
| 新增一种**像素算法** | ❌ | 算法在 mask ROM；`.BIN` 无载体 |
| 新增一组**调校参数** | ❌ | 参数源在 `0x7E5C9809` / `0x7E8973D0` |
| 新增一条**色调曲线 / LUT** | ❌ | E-P5 四个块里都没有曲线表（§1.5） |
| 在菜单里**新增一项** | ❌ | 菜单描述符在 `0x7E452BDC` / `0x7E452BE4` |
| 改菜单项的**显示文字** | ✅ | 块 1，等长替换 |
| 把某个已有滤镜**改指向另一组 ROM 参数**（变体） | ✅ | 1 个 4 字节立即数（`FUN_40788AFC` / `FUN_4078849B` 里的 `mov <ROM>,a0`） |
| 让**录像菜单多出 6 项** | ⚠️ 半可行 | 需把录像路径的类型码改成照片那档（`FUN_405731F7` 的 `+0x6B = 4` → `0`），
**但前提是那两张描述符里真的有 10 项 / 4 项之别** —— 需 mask ROM 才能证实 |
| 把 AF 修复**搬进 `.BIN`** | ❌ | 修复实体在 mask ROM，官方 `.BIN` 本身都不承载（第十七轮） |

## 3. 结论对项目目标的影响

| 目标 | 现状判定 |
|---|---|
| **A 容器破解** | ✅ 完成 |
| **B AF 修复定位** | ⚠️ **实质上没有交付物** —— 修复不在 `.BIN` 里；已把范围压到 `fcs_lens_mfts` 模块，但拿不到补丁字节 |
| **C 艺术滤镜实现定位** | ✅ 完成（13 模块 / 两套 ID 命名空间 / 三张名字表） |
| **D 解锁录像艺术滤镜** | ✅ 代码层 3 处 + 资源层 1 处已定位；**单字节补丁点已确定**（`FUN_405731F7`） |
| **E 新增创意滤镜** | ❌ **在 `.BIN` 层面不可行**（本文件 §2）；可行的是「参数变体」与「菜单文字替换」 |
| **G 块 2 的 6-bit** | ⛔ 跨 30 个固件恒定，统计法已排除（第十六轮） |

⇒ **项目剩下真正有价值的，只有一件事：拿到机身 mask ROM 映像。**
它同时决定 B（AF 修复）、E（新增滤镜）、D（录像菜单能否多 6 项）三个目标。

# 块 1 资源分区内容分类

    --targets <块文件>[:基址] ...
