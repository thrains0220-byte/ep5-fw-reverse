## 1. 容器两层结构（观察）

Olympus `.BIN` 外层容器（仓库 `tools/oly_container.py` 已完整实现）：

```
块 = [32B 头][payload(混淆)][32B 尾]
头/尾 : "OE"/"OM" + 机型(2B) + 0 + 运行地址(u32) + payload长度(u32)
        + 版本(u16) + 0 + kind(u16) + 0 + 0(u32) + 0(u32)
校验  : (sum32(头) + sum32(payload) + sum32(尾)) mod 2^32 == 0，尾[28:32] = 校验值
混淆  : 16 字节组内按 DECODE_ORDER 做字节平面转置 + 按位取反
```

**新发现**：某些分区的 payload 内部**又嵌了一层容器**（"OE" 头出现在 decoded payload 的 0x3E0 处）。
内层（运行映像）格式与外层不同：

```
块 = [32B 头][payload(明文，无混淆)][32B 尾]
头  : "OE"/"OM" + 机型 + 0 + 运行地址(u32) + payload长度(u32)
      + 版本(u16) + 0 + kind(u16=0x0006) + 0
      + 构建时间戳(u32)  <-- [24:28]
      + 0(u32)             <-- [28:32]
尾  : 头的前 28 字节 + 4 字节 0
```

内层 payload **不混淆**，且 **没有加性校验**；其头部 `[24:28]` 字段见 §2。

证据（E-M10 II v1.4，`dec4/OLY_E_120_1400_0000_0000/decoded/02_0106_43160020.decoded.bin`）：

```
解码后 payload 偏移 0x3E0: 4f 45 12 00 00 00 00 00 00 04 16 43 c0 fb 7f 00
                           00 10 00 00 00 06 00 00 00 1d cb 11 5c 00 00 00 00
                           ^^ "OE" + 机型 0x1200(E-M10 II)  ^^地址 0x43160400
                                                          ^^长度 0x7FFBC0
                                                     ^^kind 0x0006  ^^[24:28] 时间戳
```

## 2. 每块 Unix 构建时间戳（观察 + 推断）

内层运行映像块头 `[24:28]` 解释为 Unix 时间戳（UTC）时，得到合理的构建时刻，且**同一映像内相邻块相差 1–3 秒**（符合"打包器逐块盖时间戳"的写入行为）。

| 固件 | 内层块数 | 时间戳（UTC） | 备注 |
|---|---|---|---|
| E-M10 II v1.3 | 7 | 2018-04-11 00:49:04 … 00:49:08 | 其中 1 块为 0 |
| E-M10 II v1.4 | 7 | 2018-12-13 02:59:41 … 02:59:53 | 其中 1 块为 0 |
| E-P7(1300) v1.2 | 11 | 2018-12-13 09:16:39 … 09:16:54 | 同日构建批次 |
| E-M1(1090) v4.6 | 9 | 0（旧打包器未写时间戳） | |
| E-PM1(1130) v1.4 | 7 | 0 | |

**独立佐证（观察）**：代码块内嵌 C 编译器日期串与时间串同步变化：

* v1.3 新增/保留：`Apr 11 2018`、`04/11 10:02`、`09:57:34`
* v1.4 新增/保留：`Dec 13 2018`、`12/13 12:18`、`12:10:45`、`12:10:46`

**推断**：`[24:28]` = 该块被打包时刻的 Unix 时间戳。**未知**：官方是否用同一字段记录其它元数据。

> 实用价值：时间戳给出了**跨机型/跨版本对齐同一逻辑块的天然锚点**，比"按地址对齐"稳健得多。

## 3. `kind 0x106` = 资源容器（观察）

新版机型（E-M1 v4.6 / E-M10 II / E-P7 / E-PM1）的 `kind 0x106` 分区，内部是运行映像；其首块 payload 的**开头是一张资源目录**：

```
40 条 × 16 字节： { u32 运行地址, u32 大小, u32 0, u32 0 }
```

E-M10 II v1.4 的目录（首地址 0x43160800 为该机基址）：

| # | 运行地址 | 大小 | 内容（观察） |
|---|---|---|---|
| 0 | 0x43160800 | 0x240000 | **六比特 blob**（见 §4/§5） |
| 1 | 0x433A0800 | 0x84200 | 图像/资源（头 `03 28 3d 13 …`） |
| 2 | 0x43424A00 | 0x49400 | 以 `00 28 a0 02 8a 00 28 a0` 开头的数据表 |
| … | … | … | 共 40 条 |
| 30–39 | 0x43838800… | 0xA200 ×10 | 10 个等长小资源 |

E-PM1(1130) 的同一分区里还含 **14 个完整 JPEG**（4608×3456、3456×3456、640×480、1280×720 等），
即该分区不只有代码侧资源，还带**原始示例照片**。

**观察**：E-P5 v1.8（2012 代）的 `kind 0x106` 分区**只有**六比特 blob（无目录、无 JPEG），
说明该分区格式在 2012→2015 之间被重构过（资源容器化）。

## 4. 六比特 blob 的跨机型/跨版本不变性（观察）

blob 定义：E-P5 v1.8 解码后块 2 中 `payload[0x3E0 : 0x3E0+0x240000]`，
长 2,359,296 B，内容全部 ≤ 0x3F。

以该 blob 的前 4 KB 为探针，在下列固件中**全部命中且整段 2,359,296 B 完全一致**
（SHA-256 `93c4e55881cde2ae…`）：

| 固件 | 机型 | 版本 | 探针偏移（decoded 块 2） |
|---|---|---|---|
| E-P5(1080) | E-P5 | 1.8 | 0x3E0 |
| OLY_E_085/086/087 | E-P7 家族 | 1.6 | 0x3E0 |
| OLY_E_100 | E-M10 | 1.6 | 0x3E0 |
| OLY_E_101 ×3 | E-M10 III | 1.4 / 1.5 / 1.6 | 0x3E0 |
| OLY_E_112 | E-P3 | 1.4 | 0x3E0 |
| OLY_E_113 | E-PM1 | 1.4 | 0x7E0 |
| OLY_E_109 | E-M1 | 4.6 | 0x7E0 |
| OLY_E_120 ×2 | E-M10 II | 1.3 / 1.4 | 0x7E0 |
| OLY_E_130 | E-P7 | 1.2 | 0x7E0 |

**结论（观察 → 推断）**：该 blob 是**平台级静态资源**，从 2012 到 2017（E-M1 v4.6 / E-M10 II v1.4 / E-P7 v1.2）
**内容恒定不变**。

**推断（C6）**：因此它**不可能**是任何版本差异（含 2018-12-18 松下镜头 AF 修复）的载体；
把 2018 修复定位在六比特层上的假设可以排除。

## 5. 六比特层的结构分析：统计法失效（观察）

对 blob（2,359,296 B）实测：

* **符号集**：63 个（0x00–0x3B, 0x3D–0x3F）；**`0x3C` 一次都没出现**（缺席是结构性的，非偶然）。
* **熵**：5.8326 bit/byte（6 bit 符号空间的上限 6）。
* **符号频率**：全部量化到 **1/256 的整数倍**（0x02→2.99、0x00→2.49、0x03→2.00、0x01→2.00、
  0x05→1.76、0x07→1.51、0x0A→1.50、0x04→1.25、0x0E→0.76、0x26→0.25 …，相对 1/64）。
* **残余类结构**：对 k = 2,3,4,6,8,12,16 … **每一个残余类都出现全部 63 个符号、分布几乎完全相同**
  ⇒ **不存在比特平面转置 / 定长记录步长 / 4:3 重打包对齐**。
* **逐 bit 概率**：bit0 53.2%、bit1 50.8%、bit2 46.1%、bit3 43.8%、bit4 41.0%、bit5 38.3%，
  且在 k=4、k=8 的各残余类内**完全一致** ⇒ 与位置无关。
* **自相关**：shift1 = 0.0199（= Σp² 的理论基线），shift2/3/64/1024 均在 0.015–0.026 ⇒ **无任何周期**。
* **4:3 重打包反解**（4 符号 → 3 字节）得到的字节流 40% 可打印 ≈ 随机水平（37%），**不是文本/结构数据**。

**推断**：该层是**熵编码（定长 6-bit 码字或算术/范围编码）**或**不透明二进制**，
其"解码器"不在 `.BIN` 代码块里（块 0 全量反汇编中**没有**任何指令以立即数引用
`0x43DA0400` / `0x43DA0020` / `0x43DA0000` / `0x427C0800`；分区地址只能经由运行时表间接取得）。

**未知**：解码器很可能在 **mask ROM（0x7Exxxxxx）** 内——而 mask ROM 映像已被证明既不在 `.BIN` 也不在官方更新包中（见
`af_fix_instr_level_negative_result.md` §5.1 P0 四检验）。

> **方法论结论**：对该层，差分探针 / 频率分析 / 对齐分析**全部无效**；
> 只有拿到解码器（或 mask ROM 映像）才能继续。

## 6. 新差分样本：E-M10 II v1.3 → v1.4（观察）

这是本轮最有价值的**可复现差分对**，且**构建时间恰好覆盖 2018-12-18 松下镜头 AF 修复发布窗口**。

| 项 | v1.3 | v1.4 |
|---|---|---|
| 构建时间（内层块时间戳） | 2018-04-11 00:49:04–08 UTC | 2018-12-13 02:59:41–53 UTC |
| 编译器日期串 | `Apr 11 2018` | `Dec 13 2018` |
| 块 0（代码） | 21,364,672 B | 同长 |
| 块 1（数据, kind 0x101） | 27,262,912 B | **逐字节完全相同**（差异 0 B） |
| 块 2（资源, kind 0x106） | 20,971,456 B | **仅 48 B 差异**，全部落在 12 处 4 字节字段 |
| 块 0 差异 | — | 2,290,985 B（10.723%），231,959 个区间 |

块 2 的 48 B 差异 = 11 个内层块头的**构建时间戳** + 1 处尾部校验字段：

```
差异区间: 0x0003F8, 0x7FFFD8, 0x7FFFF8, 0x8FFFD8, 0x8FFFF8, 0x97FFD8,
          0x9FFFF8, 0xCFFFD8, 0xCFFFF8, 0x11FFFD8, 0x11FFFF8, 0x1213FD8
```

**⇒ 观察**：v1.3 → v1.4 的资源侧**内容零变化**，变化全在时间戳。

块 0 的差异形态与此前 E-PM2/E-M5 的发现一致：**mask ROM 重链接导致的立即数位移**。
例如 `disp=0x1C` 的镜头相关簇整体右移 **+0x1F**：

```
v1.3 簇 @ 偏移 0x530B2E..0x530CA9   (13 个 movbu)
v1.4 簇 @ 偏移 0x530B4D..0x530CC0   (13 个 movbu)     0x530B4D - 0x530B2E = 0x1F
```

同一偏移保持不变（可作锚点）的簇（本轮实测）：

| disp | 偏移区间 | 两版是否同址 |
|---|---|---|
| 0x02 | 0x26412B..0x2643A9 | ✔ 同址 |
| 0x12 | 0x13D4A6..0x13D5CA | ✔ 同址 |
| 0x02 | 0x166F78..0x1671C5 | ✔ 同址 |
| 0x01 | 0xEA466B..0xEA47D7 | ✔ 同址 |
| 0x12 | 0x13DEA4..0x13DF78 | ✔ 同址 |
| 0x1C | 0x530B2E… | ✘ 右移 +0x1F |

**未知**：v1.4 的代码侧是否真的包含松下镜头 AF 修复——**尚未验证**（需要定位镜头 ID 比较链并比对前缀集合）。
已确认的工具链：`tools/lens_prefix_chain.py`（E-M10 II 上默认参数 `disp=0x0F` 找不到链，需改用 disp 扫描）。

### 6.1 【补充·已定位】E-M10 II 的镜头 ID 处理代码：v1.3 与 v1.4 **逐指令相同**

E-P5 的镜头 ID 前缀比较链有极强的指纹序列 `90 0e f1 78 f0 40`
（`mov 14,a0` / `add a2,a0` / `movbu (a0),d0`）。用它在 E-M10 II 两版块 0 中扫描：

| 固件 | 指纹命中 | 运行地址（规范换算） |
|---|---|---|
| E-P5 1.8 | 4 处 | 0x403B79A9（其中 1 处即已知比较链） |
| E-M10 II v1.3 | **1 处** | 0x4083C6F2（payload 偏移 0x53C6D2） |
| E-M10 II v1.4 | **1 处** | 0x4083C711（payload 偏移 0x53C6F1） |

两处**相差 +0x1F**（与全块 mask ROM 位移一致）。

**指令级比对结果**：该函数及其被调函数（`0x4083CCB6` / `0x4083CCD5` 起的镜头 ID 查表段）
在 v1.3 与 v1.4 中**逐条指令完全相同**，差异只有：

| 类别 | v1.3 | v1.4 | 差 |
|---|---|---|---|
| 代码地址 | — | — | **+0x1F**（全块统一位移） |
| RAM 常量 `0x6189B728` | 0x6189B728 | 0x6189B738 | **+0x10** |
| RAM 基址 `0x618A14E4` | 0x618A14E4 | 0x618A14F4 | **+0x10** |
| 镜头 ID 指针表 / 16 位数组基址 | 0x618A14E4 / 0x618A14FC | 0x618A14F4 / 0x618A150C | **+0x10** |

镜头 ID 处理实为**查表**（RAM 指针表 + 16 位索引数组），不是比较链；
但无论哪种形态，**这段代码在两个版本之间没有语义变化**。

镜头主表（payload 偏移 0x17A3E0，运行地址 0x4047A400，90 条 8 字节记录，
厂商码 A0/B0/B1/B2/C0/C1）**720 B 逐字节完全相同**。

**镜头子系统字符串区**（`LENS_MAIN` / `LENS_ASKDATA` / `[lens] IS update error!` 等 922 条，
地址在两版中完全相同）内，块 0 的差异仅 **160 B / 127 个小区间**（全部是重链接位移）。

**结论（观察 → 推断）**：
> **E-M10 II v1.3 → v1.4 在镜头子系统的代码与数据上都没有语义变化。**
> ⇒ 若 v1.4 确实含松下镜头 AF 修复，该修复**不在镜头 ID 处理路径上**；
> 这与 E-P5 的既有结论（修复实体在 mask ROM，`.BIN` 内只体现为重链接）**方向一致**。

**仍未验证**：v1.4 是否真的含松下镜头 AF 修复（缺少"修复内容"的独立证据，
例如官方更新说明中的变更条目、实机行为差异）。**不能仅凭 `.BIN` 差分断言**。

## 7. 地址约定更正（观察，待复核）

仓库 `tools/oly_container.py` 与 `decoded/manifest.json` 定义的**规范**换算是

```
运行地址 = header_address + 0x20 + payload_offset          （= container_payload_address + payload_offset）
```

块 2 的**自证**（决定性）：

```
块2 header_address      = 0x43DA0000
payload[0x00..0x03]     = 0x00240000   （载荷长度）
payload[0x04..0x07]     = 0x43DA0400   （载荷自身的运行地址字段）
payload[0x08..0x3DF]    = 0xFF 填充
payload[0x3E0..]        = 六比特数据（长 0x240000，恰等于长度字段）

规范换算：0x43DA0020 + 0x3E0 = 0x43DA0400  ✔ 与自述地址一致
旧换算  ：0x43DA0000 + 0x3E0 = 0x43DA03E0  ✘ 差 0x20
```

而本项目此前发布的 E-P5 坐标（如镜头链 `0x403B7A0B`、LENS_INFO `0x405E8EE0`）
是用**基址 `0x402C0000`** 解读 decoded payload 得到的，即比规范换算**低 0x20**。

**更正后的 E-P5 v1.8 关键坐标**（payload 偏移不变，运行地址 +0x20）：

| 语义 | payload 偏移 | 旧（基址 0x402C0000） | 规范（+0x20） |
|---|---|---|---|
| 镜头 ID 链函数 | 0xF7989 | 0x403B7989 | **0x403B79A9** |
| 链内 mask ROM 指针 `mov 0x7E43018C,a0` | 0xF7A0B | 0x403B7A0B | **0x403B7A2B** |
| 白名单开关字 `0x605339A0` | 0xF7A27 | 0x403B7A27 | **0x403B7A47** |
| LENS_INFO 主表 | 0x328EE0 | 0x405E8EE0 | **0x405E8F00** |
| 6 张 mask ROM 指针表 | 0x402E4DC… | 0x405EE4DC… | **0x405EE4FC…** |

**状态**：这是**观察级**结论（依据：容器工具的规范定义 + 块 2 自述地址 + `manifest.json` 的
`container_payload_address` 字段）；但因历史证据链已按旧基线书写，**统一更正需与既有文档一并复核**，
本轮只做标注，不批量改写历史文件。
