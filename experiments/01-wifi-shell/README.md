# 实验 01：E-P5 原生 Wi-Fi 诊断入口

**目的：**验证原生 SD 参数导入能否启动 Wi-Fi 诊断服务，为图像管线研究取得运行信息。这个实验没有实现胶片模拟。

文件仅含 `F971=1` 一项参数，没有 BIN、程序或刷机包。原版 E-P5 1.8 的 CSV 解析、RAM 覆盖、读取和启动条件已在离线模型中验证；整机文件发现、启动顺序及无线行为尚未实测。历史修改版固件的表现可能不同。

## 实机操作

1. 使用已备份照片、可由相机正常识别的 SD 卡。若已有 `PARAMDT` 目录，先备份并查看，不要覆盖或混用已有实验参数。
2. 将本目录的 `PARAMDT` 文件夹复制到卡根目录，与 `DCIM` 并列。只复制这个文件夹；不要加入任何固件 BIN。
3. 安全弹出卡，关机插卡，再正常开机。观察约 30 秒，记录是否正常开机、是否出现与平时不同的 Wi-Fi 网络。此时无需 USB 连接，也不用进入固件升级流程。
4. 首次只观察。若出现网络，记录名称及相机表现，再进行连接协议核对；暂不发送内存、参数写入、擦除或固件命令。
5. 结束时关机，通过读卡器移走这次新增的 `PARAMDT/CP000001.CSV`，再重新开机。不要在开机时拔卡。若之前有自己的文件，恢复备份。

原生代码支持清除 RAM 覆盖，但尚未证明所有关机、休眠和热插拔场景都清除得一样；移除文件后的实际恢复行为也要记录。没有观察到网络不等于没有读入参数，不能据此继续叠加其它参数。

## 需要返回的观察

- 相机菜单显示的机身固件版本。
- 能否正常开机、拍摄和回放。
- 是否出现新的 Wi-Fi 网络；不必公开密码、序列号或含这些信息的二维码。
- 移除该文件并重新开机后是否回到平时的行为。

调试服务可能开启无认证的网络入口。请在受控环境中短时测试；它不是日常拍摄应长期保留的设置。

## 回到开发端

协议确认后，先使用 `help` 等经核对的查询命令。后续 dump 命令要逐个核查锁、内存与存储副作用，不能因为名字是“dump”就认定只读。

如果无法使用读卡器，这一步暂时无法开展；已有离线代码、来源及测试保存在项目中。
