## 上游复用与限制

- E-M10 的 `external/em10-fw/notes/menu.md` 和 `plugins/loader/hbui.c` 展示原厂菜单控制器接键、自绘页面的做法；不同机型地址不可移植。
- E-M10 上游记录 GUI 回调直接读取 SD 曾使真机死锁，须研究 E-P5 文件任务的消息/回调以及结果所有权后再接入；不得在按键或绘制回调里直接读取卡。
- Caduceus E-P7 的 `docs/RE_UI.md` 第 7 节把独立页面分成先转到原厂页、再添加自定义控件；这是设计线索，不是 E-P5 的实现证据。其 HSLFX 复用 E-P7 自带色轮，不能证明 E-P5 有同一控件。
- `flatpanda/om-emu` 的 `4b24000b0a17fde4a810952c3de4fd1ec046a77d` 版 `emu/src/fw/models.mjs` 未列 E-P5，现有 GUI 模型不能直接运行本机固件。若移植，须独立验证固件映射、任务启动、按键、显示、资源和文件任务；其模拟也不能替代真机拍摄验证。

## 下一项具体工作

1. 从相邻候选指针反向定位表的边界与注册方式，确认 ART 菜单状态对象构造、按键分发、退出清理和屏幕绘制函数。
2. 建有界模拟夹具，验证上下、确认、返回及重绘，不假定猜测出的地址是函数入口；先以原厂只读行为作为对照。
3. 确认可写内存的所有权和 UI 生命周期，设计固定容量文本及选择状态；SD 索引由已确认的文件任务读取并将快照交给 UI。之后验证缺卡、损坏文件、切换、退出及重启。
4. 完成实际 JPEG 链路后再接 LUT 应用；功能、状态显示和拍摄数据必须一致。任何一步未达标都不发布刷机包。

## 2026-11-14：原厂 GUI 状态机与 ART 事件矩阵（静态分析）

以下均是 MAIN 的静态反汇编和数据交叉引用，没有设备执行、绘制结果或可刷补丁。入口边界使用已知调用目标；不把字节匹配当成完整调用图。

### 状态机初始化和事件分派

- `0x7eab79e7..79f9` 把地址 `0x6079f888` 作为对象，调用 `0x7eab76b1`，然后写入全局 `0x602bedd0`，并通过 `0x7eab76c7` 保存另一份。`0x7eab76b1` 加载描述符指针表 `0x7ed882b4`、D0=18、D1=1、调用栈参数 2，调用 `0x7eab76e5`。后者初始化 32 字节对象，`+0=1`、`+1=2`、`+2=18`、`+4=表指针`，并设置 `+16=0x7eab775c`、`+20=0x7eab787a`、`+24=0x7eab7890`。此处 1、2 是初始选择字节，具体产品状态名尚未证明；18 是指针表入口数的有力证据。
- `0x7eab78d6` 由对象 `+0`（1 起算）从对象 `+4` 的指针表选 descriptor。`0x7eab7b4f..7b65` 从栈取事件及参数，以 `0x602bedd0` 对象调用 `0x7eab7761`；它是 `0x7eab775c` 保存寄存器及栈帧序言之后的入口，调用者已指定 `[d2,d3,a2,a3],48`。不能误把两个入口视作相同调用约定。
- `0x7eab789f` 使用 descriptor 的 `+6` 半字作为扫描次数，扫描 `+16` 指针指向的八字节 `(事件值, 行索引)` 项。`0x7eab775c` 检查行索引小于 descriptor `+2`，用 `行索引 × descriptor[0] + (当前状态-1)` 访问 descriptor `+8` 矩阵；以该矩阵元素为索引从 `+12` 函数表选择并调用回调。回调返回的高、低字节分别参与更新对象 `+0/+1`，切换时依次调用旧 descriptor `+24` 和新 descriptor `+20` 所指数组的状态函数。代码路径支持把它们称为状态退出/进入回调数组；具体每个函数的绘制、资源和副作用仍未全部确认。
- ART descriptor `0x7edc0284` 四个半字是 `(11,64,183,64)`；`+8=0x7edbff6c`、`+12=0x7edbfc90`、`+16=0x7edbfa90`、`+20=0x7edc022c`、`+24=0x7edc0258`。前两个计数直接用于矩阵索引/事件行边界，第三项与回调数量一致，第四项用于映射表扫描。11 对应状态列，64 对应事件行；183 的消费点需另证。矩阵为 **64 × 11 个字节**；元素是回调索引，而非直接的转移目标，转移来自回调返回值。
- 例：事件映射 `0x9031→19`，其第 5/6 状态矩阵元素为 59/61，零起算函数表相应地址 `0x7edbfd7c/84` 指向 `0x7eaf1fa3/0x7eaf2223`；`0x9032→20` 的第 5/6 状态元素 60/62 对应 `0x7eaf2fb3/0x7eaf322a`。后两个邻接函数的日志分别为 **StScnMenu** 拨轮/控制环，因此不能把所有相邻回调都称为 ART。`0x9031/0x9032` 与两类控件有关，但物理按键映射及上游事件生成还需验证；回调内部传给菜单对象的 11/12 与状态机事件码属于不同层。
- 11 个进入函数数组从 `0x7edc022c` 起，退出函数数组从 `0x7edc0258` 起；第 5 项退出函数是 `0x7eaf46e8`，其中日志是 `StArtMenu_Exit`。这将先前发现的退出函数与矩阵状态第 5 列关联起来，但不能由此推断所有行的绘制函数。

### 菜单对象、启动和绘制缺口

`0x7eb1e11d` 依据输入枚举分支选择对象，并在 `0x7eb1e1ea`、`0x7eb1e2f1` 等处写 `0x602c0d1c`；其前面先将现有对象传 `0x7eb1edc7`。其中若干分支调用 `0x7eb1be6e`：它在 50 项对象缓存中按 ID 查找，未命中时从 `0x7edf10ac` 的 77 条 `(u16 ID, 构造函数指针)` 候选记录查找并间接创建；替换缓存槽时会经对象虚函数或 `0x7e890203` 清理。尚未确认哪一个 ID 是 ART 菜单对象、其构造函数与 vtable 内容，因此不能把通用对象缓存当作已恢复的 ART 对象生命周期。

ASCII `EVT_START_ART_SELECT` 在 `0x7eded678`，被字面引用于 `0x7edeee60`；`START_ART_SELECT` 在 `0x7ec69e8a`，被引用于 `0x7ec6a730`；`GUI_END_ART_SELECT` 在 `0x7ec66f89`，被引用于 `0x7ec68590/0x7ec68978`。这些引用落在数据区域，当前尚不能建立启动调用链。此前 `filtlist / ART DISP FILTER LIST` 是处理任务调试命令而不是屏幕绘制：`0x7e3fdae3` 调 `0x7e40af02`，后者返回 `0x605f57e4 + index × 676`（index ≥ 8 返回空）；`0x7e40b3ab/0x7e40b3f9` 调 `0x7e40b511` 写处理任务。它不应拿来充当 GUI 项目列表。

结论：加入 descriptor 虽是可研究路线，但**不等于增加了可用独立菜单**：仍需确认进入/返回事件、实际启动链、绘制对象和布局、文本生命周期、对象 ID/vtable、选择保存及成像链。也可研究在 ART 状态内部进入子页面；两种方案须先用模拟执行确定，不依据表结构冒然做固件补丁。

## 2026-11-14：事件查找探针

新增 `tools/ep5_ui_event_probe.c` 与 `tools/validate_ui_event_probe.py`。探针在固定的 E-M10 CPU 仿真器提交 `6adb3bef36239859ae3fcd94b0dbb7db6de6ffa1` 上执行 E-P5 原厂 `0x7eab775c` 分派，使用合成状态对象和有界栈，不读相机、不写固件：

- 64 个事件键及其行号查找通过；未知事件拒绝；栈和非易失寄存器保持。
- `0x9031` 与 `0x9032` 分别选择 `0x7eaf1fa3`、`0x7eaf2fb3` 两个 ART 拨轮/控制环回调入口。
- 探针在回调入口停止，未执行回调本体，也未证明事件由真实按键生成、状态转移、绘制、文本显示、保存或真机可达。

运行：

```text

```

这一层验证说明原厂事件矩阵可作为后续 UI 模拟的边界。它没有提供一个可直接复制的“新增菜单项”接口；新增页面仍须补齐进入/返回事件、对象生命周期、绘制数据和保存状态。

## 2026-11-14：菜单快照核心

`firmware/lut_menu.{h,c}` 实现了一个与原厂回调返回约定相容的最小状态核心：`0=未显示`、`1=加载中`、`2=就绪`、`3=错误`；方向键移动三项，OK 返回提交，返回键返回上层。`firmware/lut_menu_index.{h,c}` 在文件任务提供的 `ep5_look_io` 上读取并校验 `EP5LUT/INDEX.EP5`，只接受针孔 I/II/III 三个目标槽，完成后一次性发布名称、风格编号和强度快照；代号不匹配、短读、坏 CRC、重复槽和非法名称进入错误状态，不污染上一份已发布快照。

该核心通过 `tests/test_lut_menu.c`、`tests/test_lut_menu_index.c` 的固定 C 测试。它尚未与 `0x7eab775c` 的真实状态对象、显示绘制、文件前台任务唤醒或 JPEG 钩子连接；因此它是可审阅的机内 UI 逻辑基础，不是刷入即可显示的页面。
