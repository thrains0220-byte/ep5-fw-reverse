## 上游复用与限制

- E-M10 的 `external/em10-fw/notes/menu.md` 和 `plugins/loader/hbui.c` 展示原厂菜单控制器接键、自绘页面的做法；不同机型地址不可移植。
- E-M10 上游记录 GUI 回调直接读取 SD 曾使真机死锁，须研究 E-P5 文件任务的消息/回调以及结果所有权后再接入；不得在按键或绘制回调里直接读取卡。
- Caduceus E-P7 的 `docs/RE_UI.md` 第 7 节把独立页面分成先转到原厂页、再添加自定义控件；这是设计线索，不是 E-P5 的实现证据。其 HSLFX 复用 E-P7 自带色轮，不能证明 E-P5 有同一控件。
- `flatpanda/om-emu` 的 `4b24000b0a17fde4a810952c3de4fd1ec046a77d` 版 `emu/src/fw/models.mjs` 未列 E-P5，现有 GUI 模型不能直接运行本机固件。若移植，须独立验证固件映射、任务启动、按键、显示、资源和文件任务；其模拟也不能替代真机拍摄验证。

## 下一项具体工作

1. 从相邻候选指针反向定位表的边界与注册方式，确认 ART 菜单状态对象构造、按键分发、退出清理和屏幕绘制函数。
2. 建有界模拟夹具，验证上下、确认、返回及重绘，不假定猜测出的地址是函数入口；先以原厂只读行为作为对照。
3. 确认可写内存的所有权和 UI 生命周期，设计固定容量文本及选择状态；SD 索引由已确认的文件任务读取并将快照交给 UI。之后验证缺卡、损坏文件、切换、退出及重启。
4. 完成实际 JPEG 链路后再接 LUT 应用；功能、状态显示和拍摄数据必须一致。任何一步未达标都不发布刷机包。
