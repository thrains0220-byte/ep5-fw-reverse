# E-P5 1.8：哪些 ART 槽可以复用

机身保持官方 1.8。本页只分析原厂解码数据，运行 CPU 模型；没有生成更新文件或访问相机。

**选三个既有物理槽，针孔 I、II、III 是目前证据最充分的一组。** 在原厂拍照参数构造中三者分别得到模式 73、106、108。三种模式的色度表位于不同地址，但每张都和另一个选择器共享，也都会继续运行针孔滤镜。现有 RC2 只改过 I，不能直接把候选扩写成三个独立且无副作用的槽。即使解决隔离，两条一维色度曲线仍不能实现任意 RGB 三维 LUT。

## 实际跑过哪些路径

[只读入口](../tools/inspect_art_slots.py)核对官方 MAIN 与语言块的 SHA-256，解析选择器跳转表以及简繁体字符串表。[目标指令探针](../tools/ep5_art_slots_probe.c)在同一 MAIN 上分别运行两项检查：

- 原厂 REC 包装入口 `0x7e3ed7e6`：在合成上下文设置 `+17471` 和 `+18147`，分别遍历设置值 100..202 和变体 1..3，固定 level=200、附加效果全关。执行至 `0x7e3ed818`，读取 packet 模式及资格判断。仅 gate=0 时调用原厂列表构造 `0x7e40b368`，记录任务入口及入口引用的原厂日志名。309 组中 62 组返回有效模式，32 组进入此 ART 列表。设置号不是菜单顺序或 EXIF ArtFilter 号；探针能写入某个设置，不代表机身开放了这个选项。
- 单独从原厂调用点 `0x7e22df5b` 运行 256 个模式的色度选择器和驱动参数生成器，逐项取出 6 个表指针、34 个打包字。辅助输入固定为零；默认分支未能取得真实运行时 RAM，采用现有探针的明确替身。将两个结果按模式号对照是离线关联，不表示每个场景都从快门一路运行到了 ISP。针孔另有[既有捕获探针](../tests/test_native_film_route.py)独立串接选项、作业与驱动。

下表给出**确实进入这个 ART 任务列表**的设置。I/II/III 只在已经明确对应机身变体时作为产品名称使用；其余用原厂日志名或其含义。数字是模式值，不是对固件的修改指令。

| REC 设置 | 有效模式（去重） | 原厂追加的处理 | 色度表共享者 |
| --- | --- | --- | --- |
| 101、113 | 69 | soft_focus；两个设置也共享此处理 | 69/78 |
| 104 | 74、104 | rough_monochrome，输入为另一条 `art_stl2ycc2` | 两者都走默认分支 |
| 105（针孔 I/II/III） | 73、106、108 | pinhole，同一入口 `0x7e40115c` | 73/82、106/107、108/109 |
| 106 | 86 | diorama | 86/88 |
| 108 | 91 | gentle_sepia | 91/93 |
| 109 | 96、165 | dramatic_tone，输入为 `art_stl2ycc2` | 96/97/165/166 共用一组；两轴也共表 |
| 115 | 118 | star_light | 118/122 |
| 117 | 151 | mirror | 默认分支 |
| 118 | 153 | composite | 153/154 |
| 119 | 163、169 | artclearline | 均走默认分支 |
| 120 | 181、182 | pastel_art | 均走默认分支 |

另有原厂 REC 设置能得到模式号、但在本次输入下 **gate=1，不走上述任务列表**：100→70/102，102→71/145，103→72，107→85/167，110→145，111→75，112→84，114→117，116→119，201→188，202→189。不能由此推断它们不可拍摄，也不能把它们计入可执行软件 LUT 的槽数。

## 为何复制一条曲线会影响其他选项

在 `0x7e229ff0` 的色度选择器中，ROM 跳转表 `0x7e478e90` 的第一个槽对应模式 69，最后一个对应 168。16 组分支各引用一个连续 98 字节的表对，每组均由两个模式号共享。另有一组 4 个模式共用相同指针；其余 220 个模式在本次辅助输入下走同一默认路径。**256 个模式里，没有一个在这次测试中独占自己的六指针组合。** 相同的 98 字节也常出现在不同的地址；不能用搜寻恒等表字节来确定某个菜单项目。

| 针孔槽 | 模式与共享模式 | 两轴起点（CPU 地址） | 除选择器外，首个表地址还被何处字面引用 |
| --- | --- | --- | --- |
| I | 73 / 82 | `0x7e438bb0`、`0x7e438be1` | `0x7e21d0d1` |
| II | 106 / 107 | `0x7e438dfc`、`0x7e438e2d` | `0x7e21d3e9` |
| III | 108 / 109 | `0x7e438e5e`、`0x7e438e8f` | `0x7e21d46d` |

三者原厂表内容相同，实际运行色度 writer 得到的 34 个字也完全相同。这与同属针孔却能在成片上有所不同并不矛盾：色度表是处理的一环。已知 82 是录像路径的共享模式；表只证明 107/109 与对应照片号同分支，不据此给这两个号命名。另有录像代码本身会传入拍照号；即便隔开表项，还要分别验证取景、视频与静态成片。[RC2 对共享副本、原厂初始化与录像的检查](SOFT_CHROME.md)不能直接沿用到 II/III。

工具输出每组表的 SHA-256，以及六个指针在其他位置作为四字节常量出现的位置；这些位置是排查入口，不能证明运行时没有别的间接引用。**没有证明每个槽有独占的颜色矩阵或亮度曲线。** 交叉通道、亮度相关映射、标定颜色空间和逐像素三线性插值不能由此推得。

## 是否保留原艺术效果，是否能新增菜单

- **保留效果：** 只调原生色度参数，针孔仍走 `RAW→YC → pinhole`。黑白、移轴、戏剧等槽也有自己的附加处理。把外部 LUT 套在这些结果上，输出不等于把它施加在一张中性照片上。
- **中性化：** [原厂列表对照](NATIVE_CONTRACTS.md)在空任务上将 packet 模式设为 0、关闭附加效果，原厂只排入 `0x7e40cbb1`（RAW→YC）。这可以作为研究入口，但会丢掉原来用于区分 LUT 槽的模式值；实现必须在中性化前单独保存选中的槽，并验证所有权、同次保存、取消、普通模式、录像和完整像素格式。还没有可上机的中性多槽实现。
- **改名与新增：** 简、繁体语言组各有 2317 项；针孔普通条目 69、带图标列表条目 602。其他例子：柔焦 68/598、立体 61/603、戏剧 62/583、水彩画 1717/1718。已有 RC2 只等长换字，保留条目数、指针、图标和子变体机制。替换显示名不会创建新的 selectable ID，也不会动态生成 I/II/III 的独立标签。新增菜单槽仍需定位 UI 项目表、选择保存/恢复、变体边界、语言布局及拍照/录像分派，不能用未命名的内部设置号充当可达菜单槽。
- **安装一次以后换 SD LUT：** 原生色度表来自固件或驱动参数 RAM，本审计没有发现原厂按 ART 槽从卡读取任意 `.cube` 的证据。对桌面工具可将针孔 I/II/III 作为三个**拟用的目标槽**。要实现真正的 SD 换 LUT，仍须有经过验证的机内加载器和图像处理入口；桌面端转换、复用原菜单和数据校验不能代替这个后端。

## 复现

```sh
# 只读哈希、ROM 跳转与语言资源；Windows 的 Python 也可运行。
python tools/inspect_art_slots.py
# 加入两次目标指令遍历；需要 README 固定的 em10-fw、Git 和宿主 C 编译器。
python3 tools/inspect_art_slots.py --native
```

输出为 JSON；程序不连接相机、不写入固件或 SD。拒绝 MAIN/语言块哈希不符的输入。Native 模式仅在主机临时目录构建 CPU 探针，证据是原厂参数与函数选择，不是全幅图像处理或实机菜单遍历。
