# E-P5 外部风格数据协议 2（开发中）

此协议是桌面工具与待开发的机内通用模块之间的数据约定。官方 E-P5 1.8 不识别它；导出的 ZIP 没有升级 BIN，不能将其当作固件安装。当前 `camera_ready=false`，机内加载器尚未发布。

导出包含 `EP5LUT/INDEX.EP5`、最多 16 个 `EP5LUT/L0000001.LUT` 风格，以及 `manifest.json` 和保留原件的 `SOURCE/*.cube`。机内文件使用 8.3 名称，不依赖用户原始文件名或中文长文件名。每次处理只需要当前风格的缓存，不要求把所有 LUT 同时放进 RAM。

所有数值为小端。LUT 文件头为 `<8sHHIII`：魔数 `EP5LUT01`、边长 17、编码 1（sRGB 显示编码 RGB16）、本包风格编号、数据长度、CRC32；后面固定 29,478 字节，红轴变化最快。CRC 覆盖数据，不包含头。输入表完整保留在 SOURCE；17³ 重采样误差在清单中单独报告，不是相机的校色误差。

索引头 `<8sHHII`：魔数 `EP5IDX02`、版本 2、记录数、记录字节总数、记录 CRC32。每个 `<HBBHHI16s`（28 字节）记录包含原始 PictureMode、variant、flags=1、强度 Q8（0–256）、风格编号、预期 LUT 数据 CRC32 和 NUL 结尾的 UTF-16LE 短名。桌面短名限制为 6 个 BMP 字符，不按内部滤镜码选槽，因为原厂不同 ART 位置会出现相同滤镜码。

该预期 CRC 必须与 LUT 头及实际数据同时一致，防止索引与其他包中同编号但不同内容的表混用。CRC 用于发现损坏与意外混装，不作为对抗恶意文件的认证。协议 1 从未发布到机身；开发版 v1 索引不再接受。每次加载均重新读文件并验证，不能只凭编号复用旧缓存。

不得直接信任文件后缀、原厂读取函数的成功返回或不受限制的头部长度。未来加载器必须先检查魔数、版本、最大记录数、精确文件长度、编号一致性、CRC、强度和槽位，再将已完整验证的新表切换为活动缓存；短读、损坏或不支持的配置保留原厂路径。记录没有主机提供的指针或可执行代码。

桌面导出仅允许已由用户明确声明 sRGB→sRGB 的 LUT。V-Log、Rec.709 或未知基底可以保留在库里，但不会被静默当成 E-P5 sRGB 数据发布。预览在 RGB 色表核心中执行，不能用来证明原厂 ISP 的编码和全尺寸接入已经完成。
