# E-P5 film processing implementation plan

> Execution: implement inline in this chat. The user explicitly requested execution without another design approval round.

**Goal:** generate full-resolution film-look photographs inside the E-P5 while preserving ORF files.

**Architecture:** establish a new, exact official firmware baseline; locate the native development and pre-JPEG buffer paths independently; use a small, tested colour kernel at a verified insertion point. Desktop execution of the same kernel is a test, not the final product.

**Stack:** Python standard library for firmware evidence and LUT compilation; portable C for pixel processing; GNU MN103 binutils for disassembly. Existing upstream tools stay in ignored external checkouts.

## Requirements and constraints

- Target E-P5, not E-P7/PEN-F/E-M10 firmware or their addresses.
- Full-size output, normally 4608 x 3456 at 4:3; preserve original ORF.
- The user accepts delayed processing and prioritizes image quality.
- The camera is currently disconnected; its installed image is a previously modified, unidentified build.
- No flashable image can be qualified by host tests alone.
- Distinguish flash container addresses, CPU code addresses and image-buffer addresses.
- Do not modify vendor firmware until original instruction boundaries, ABI, code residency, buffer ownership, cache handling and a bounded disable path are established.
