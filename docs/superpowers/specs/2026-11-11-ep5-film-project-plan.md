# Olympus PEN E-P5 胶片直出项目计划任务书

2026-11-11 · 第一版 · 目标机身为 PEN E-P5，开发基线为官方 1.8。

研究起点为从 GitHub 单独检出的 [work/ep5-film，提交 b9fdb49](https://github.com/thrains0220-byte/ep5-fw-reverse/tree/b9fdb4985eca48d3d8128bdb07a7126d2cefd1bf)。

## 一、要交付的相机体验

在机身选中一个内置胶片风格，设为 4:3、最大尺寸、RAW+JPEG，单次按快门。相机自动把 ORF 和一张 **4608 × 3456** 的风格 JPEG 写入卡，回放可看，电脑能解码。切回普通模式即可拍原厂效果。允许拍后等待，首用无需电脑、手机或额外的 LUT 文件。

首版建议做一款原创暖调负片风格。先确定肤色、灰阶和高光应呈现的样子，再选择能达到目标的实现。现有 Warm Negative 可生成第一组目标样张，仍需 E-P5 样片校色。保留用户所设的曝光、ISO 和白平衡。外部 `.cube` 导入、多风格切换、颗粒、实时取景模拟、视频和连拍提速排在首版验收之后。回放显影用于实验对照，最终验收从按快门开始。

## 三、路线选择

**路线 A 优先验证原厂显影参数。** 从一个可单独选中的 Picture Mode 或 ART 子项入手，追踪其静态照片任务如何组合色彩、色调及对比度参数。优先找该子项独用的参数表，只改一项即可验证。有共享表时再评估能否给该任务单独传参。在这一次任务上试做一款内置配方，沿用原厂显影、JPEG 编码和写卡。它有机会用很小的改动得到全尺寸胶片风格。最大的未知是这些参数的表现力，以及它们能否只影响所选模式。先在原厂菜单里测出同一 ORF 本来就能做出的效果，作为对照。

**路线 B 保留真正的三维 LUT。** 若 A 只能复现普通菜单调节、影响其他模式，或无法达到事先定好的目标色彩，就用已有的 17³ RGB16 LUT 核心。复用一个可识别的 ART 拍摄入口，使原厂只做中性 RAW→YC 转换，在第一次 JPEG 编码前处理这张照片，再交回原厂保存。只在确认可写、独占的完整图像上运行。如果必须支持用户任意的跨通道调色，直接选 B。首版即使走 B，也只内置一个已校色的 LUT。若两条路线都无法在试验机通过，保留原厂使用状态，列出失败场景及复现资料，暂停发布升级包。

| 问题 | 决策 |
| --- | --- |
| 先用回放还是直接改拍摄？ | 优先用回放里的“RAW 数据编辑”固定同一输入。若候选仅在快门任务生效，使用 T5 的受控单拍对照。两种情况都要追通快门单拍到文件落盘。两条入口是否共享代码要用证据回答。 |
| 何时结束 A 的探索？ | 查完一次“入口选择 → 参数生产 → 静态图像请求 → 成片”的链路。如果只能追到日志或全局共享默认值，记录断点，转 B 的所有权和性能实验。如果确认有局部参数，就用留出的样片评估效果后定路线。 |
| 软件 LUT 能否直接打开？ | 现有模块占 31,578 / 32,752 字节，余 1,174 字节，控制记录默认关闭。80 像素暖调用例执行 69,586 条目标模型指令。应先实测条带耗时和缓存代价，再决定是否需要简化插值或缩表。模型指令数不能换算成机身秒数。 |
| 如何保留原厂行为？ | 只为选定模式、4:3 全尺寸单拍启用。关闭、其他模式和不支持的配置走原路径。优先使用独立子项。如果确需临时借用某个原厂 ART 变体，记录被占用的选项、提供关闭后恢复原效果的办法，并在机身使用说明指明。 |

## 四、任务分解与通过条件

| 顺序 | 具体工作 | 产物与通过条件 |
| --- | --- | --- |
| **T0 · 固定输入（本轮已核）** | 锁定 Git 提交、官方四块和 EXE，静态读取 E-P5 patch 清单，原版往返重包，并重建参考输出。以后只对精确原始输入应用本项目差异。 | 本文第二节的哈希和测试结果可作构建对照。任何输入哈希、预期旧字节或块校验不符，构建器拒绝出包。机身当前安装来源单列为待核。 |
| **T1 · 留下原厂样片** | 用现有机身拍固定曝光、固定白平衡、4:3 最大 RAW+JPEG，记录当前版本及已知修改历史。先拍一组同时含灰、红、绿、蓝和明暗层次的静物，再补肤色、日光与室内场景。留一组样片不参与调色。在回放中用同一 ORF 分别生成原生中性和一个原厂风格 JPEG。 | 每组保留原文件、设置、文件号和尺寸。来源尚未核实的 1.8 样片标作“当前机身”，正式原厂对照需在已知原厂基线上取得。导出后算 SHA-256，确认同一 ORF 多次显影前后未改。没有线可以先拍，原卡保留。有读卡器即可导出。 |
| **T2 · 离线追两条原厂入口** | 从两段参数读取代码逆查写入和消费者。从 `rec_art_artpacket_set_param` 的字符串引用 `0x7e3ed0d2` 和回放 `play_rec_raw_edit` 候选 `0x7e61808d` 向两端追。标明菜单/模式值、任务消息、静态图像请求、缩略图分支、编码和释放。分别标识实指令和模拟服务。 | 出一张调用表，逐个标明调用地址、原字节及上下游参数。至少给出一个有望只改变所选模式的候选点和一个普通模式对照，或写清追踪中断的位置。此项今天即可开始。 |
| **T3 · 确定颜色目标与最小补丁** | 以 T1 的中性全幅 JPEG 生成桌面目标样张。在训练样本上调暖调负片，冻结风格版本和验收口径，留出样本用于后面的真机检验。A 准备单一参数的方向性改动和一个关闭对照。B 准备恒等 LUT 和易辨认的测试 LUT。 | 交付同一 ORF 的基线 JPEG、桌面目标、候选补丁差异和预期色块变化。同一取样区、相同色彩管理转换至 Lab 后比较平坦色块。建议首轮目标为相对桌面目标的 ΔE00 中位数 ≤3、95 分位 ≤8，同时核对肤色、灰阶和高光。在 T5 前锁定这些判据。 |
| **T4 · 准备安装及恢复实验** | 核对 E-P5 可用的升级入口、同版本包是否被接受、启动失败时还有什么入口。准备已核验的原厂 1.8、精确差异清单和重新解包校验。先确认可用的试验机或独立恢复手段，再在试验环境验证开机、取卡重启及恢复原厂。 | 分别记录“机身仍可启动时的恢复”和“机身无法正常启动时的恢复能力”。确认来源、可承担试验风险前，不在机主的日用机上首刷。USB 线、正确文件名和整包校验各自只解决一部分问题。 |
| **T5 · 真机证明自己改到了成片** | A 先试单一参数，关→开→关，验证作用范围，再试目标配方。首选同一 ORF 重显影。若 T2 查明回放与快门分路、候选只在快门生效，可用固定场景与设置的受控单拍，并以各张 ORF 的原厂重显影作对照。B 先取得下节的事件记录，再试恒等与测试 LUT。 | 取得完整实验 JPEG。留出样本按 T3 冻结的口径与桌面目标对比，关闭恢复到原厂重复误差范围。若 A 的色彩不足，带着实际偏差转 B。只有缩略图变化、普通模式跟着变或错行，返回 T2 查对应分支。 |
| **T6 · 接通按快门直出** | 复用原厂模式选择和 RAW+JPEG 保存流程。追踪实际快门任务的每一张编号、完成通知、第一次主 JPEG 编码和文件写入。退出模式、重启和异常均清理本次状态。 | 单按一次得到本次 ORF 与 4608 × 3456 风格 JPEG，无需回放操作。下一张普通模式照片正常。记录开关各自拍摄到可回放、可再次拍摄的时间。 |
| **T7 · 回归与交付** | 对同一候选包做关/开/关切换、冷启动、连续单拍、回放放大、空卡/近满卡、正常拍摄后再试不支持的比例与连拍。检查普通拍摄、对焦、曝光、存储和 ORF 完整性。实际演示卸载和恢复后再重装。 | 建议工程起点为 3 次冷启动、开和关各 10 张交错单拍，覆盖多场景。所有 ORF 用独立 RAW 解码器读取传感器数据，JPEG 完整解码并核对对应文件号、尺寸、EXIF、方向和缩略图。最终交付能在 E-P5 上启用风格的升级文件、适用机型、输入与输出 SHA-256、安装与恢复步骤、样片和实测耗时。如以本地打包器分发，须能从原厂输入生成与真机验收完全相同的升级文件。回归记录同时列出卡、镜头、机身与未覆盖的配置。 |

开发者负责追踪、构建与桌面对照，机主可先采样并导出原文件。首次装入候选、验证恢复和回归由试验机操作者留存日志与原图。T1 和 T2 可并行，T3 的桌面目标和 T4 的离线准备也可并行。T5 的功能实验依赖 T4，T6 在 T5 确认像素效果后验收实际拍摄流程，T7 使用与拟交付物哈希一致的包。

### 软件 LUT 路线的三项专项验证

1. **像素和格式。** 当前代码假定 Y0/Cb/Y1/Cr、BT.601、全范围。用灰阶、彩色块及窄条高反差边界，核对通道次序、全/限范围、矩阵、传递函数、行跨距和裁切。用恒等 LUT 验证原始字节保真，再用测试 LUT 验证颜色方向和整帧覆盖。记录的 `4608 × 3456 × 2 = 31,850,496` 是原厂分配请求。还要取得这次真实分配的地址与容量。
2. **图像归谁、何时可写。** 在 T4 设计一个对像素只读的跟踪实验。先查原厂日志能否导出这些字段，缺项时才在试验机使用小型内存事件记录器，拍摄结束后经已验证的诊断读取或 SD 文件导出。记录任务、请求标识、图像地址、申请容量、完成、JPEG 交接和释放的顺序，并把实际落盘文件号与这些事件对应。持续跟踪一次成功、一次异常和一次地址复用，验证缓存失效/写回和任务串行性。若没有观测通道，B 停在离线阶段。当前回复的 token 和 packet 地址固定。用延迟回复、同址复用和重复 JPEG 请求证明处理与本次拍摄绑定，且每张只处理一次。若原厂无法给出可证明的独占期，先停写，回到只读追踪。
3. **关闭与失败。** 当前汇编接收桥在读取开关前已写入回复缓冲区的 12 字节。关闭分支须与原厂短回复、超时和错误行为对照。当前同步 JPEG 入口也没有让出调度或取消回调。先测条带和整张处理时长、看门狗及界面响应，再确定调用方式。一旦部分像素已改又失败，应丢弃工作图、从保留的 ORF 重来，阻止半张效果图落盘。[现有汇编入口](../../../firmware/ep5_art_entry.S) · [现有 JPEG 前适配](../../../firmware/ep5_art_entry.c)

## 五、这几天与数据线到手后的安排

- **现在，可离线推进。** 优先做 T2 的参数生产者和静态图像消费者对照，同时准备 T3 的恒等/测试风格与 T4 的镜像验证清单。机主若方便，只需做 T1 的原厂拍摄和同一 ORF 的回放显影。拿不到文件时先留在卡上。
- **有读卡器或数据线后。** 先导出原始样片并完成颜色目标。E-P5 手册列出的 USB 线为 **CB-USB6**。如使用机身 Wi-Fi，只接受实际可取出的原文件并核对尺寸。仓库的只读采集器尚待 E-P5 真机验证。用线导出、运行诊断和刷写分别验证。
- **关于刷其他版本。** 机身显示 1.8 与本项目的目标版本相符，无需降级。官方更新器面向最新版本，官方说明不支持通过常规流程回退。EXE 的 E-P5 配置给出 SD 安装文件名，但同版重刷、修改包启动和救砖能力都须在 E-P5 上验证。菜单显示 1.8 也无法识别某个曾刷入的改版。先核清来源，后续升级包只基于校验过的 E-P5 1.8 原厂文件构建。[官方更新说明](https://explore.omsystem.com/in/en/firmware_update_instructions) · [E-P5 说明书](https://download.omsystem.com/pages/inst/ep5/manual_ep5_ENU.pdf)

## 六、参考项目各解决什么

- **佳能 The Ritual** 展示按快门、保留 RAW、机内生成全尺寸 Print JPEG 的体验。它让等待显影成为用户看得懂的步骤，适合借鉴成片和耗时反馈。[The Ritual 机内指南](https://latentstudios.art/firmware/guide/)
- **佳能 Soup Engine / M-Film** 分别提供同一色彩引擎验证机身与桌面输出、分块显影与机型适配的参考。E-P5 的处理器、原始格式、启动与队列须单独验证。[Soup Engine](https://github.com/jiijii0/soup-engine) · [M-Film 移植说明](https://github.com/HNGSeries/mfilm-canon-film-simulation/blob/3224f66d966cdf9ede7b0ed091f9959c249d8090/PORTING.md)
- **Olympus E-M10** 在机身上观察到普通拍摄由 ISP 从 Bayer 直接编码 JPEG，特定显影路径才产生可编辑的整幅 YCbCr。这直接解释了为什么 T2 要分开追快门和回放，并验证两者实际经过的缓冲区。其硬件色度表也给路线 A 提供了查找方法。[E-M10 作者的实机记录](https://github.com/cmdada/em10-fw/blob/6adb3bef36239859ae3fcd94b0dbb7db6de6ffa1/notes/plugins.md)

**下一个里程碑是 T2 的参数调用表和 T1 的同源样片。** 调用表要能从一个可选模式追到已命名的色彩字段，再追到静态图像请求。样片要包含一份 ORF 和由它在机内生成的对照 JPEG。两者齐备后，即可制作第一个能用成片检验的候选配方。

### 执行记录（2026-11-11）
