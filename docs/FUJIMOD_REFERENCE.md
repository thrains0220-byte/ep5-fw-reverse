# Fujimod 参考与 E-P5 的落点

核查日期：2026-11-16。这是外部参考及本项目取舍，不是 E-P5 的可用功能清单。

## 第一手来源

- [Fujimod 官网](https://fujimod.com/)：页面标注 2026-11-12 更新，展示机内胶片
  编辑、卡上保存、自定义配方列表和浏览器模拟；首次发布说明以 X70 为起点，
  同时说明未在相机上测试全部功能。
- [公开仓库 README](https://github.com/justjake/fujimod#readme)：明确说明固件修改
  本体尚未开源；公开部分是相机工具、模拟器及浏览器应用。不能从公开工具库推断
  可以直接移植其胶片算法、菜单实现或 SD 双启动。
- [CI 说明](https://github.com/justjake/fujimod/blob/main/CI.md)：常规测试使用脚本化
  USB 交互和模拟对象；依赖固件、模拟器包或相机的浏览器脚本另需输入，不随常规
  CI 自动运行。因此软件测试通过与真实相机验证应分别记录。

## 本项目采用的部分

1. **机内选风格、明确当前状态。** 沿用已确定的 E-P5 菜单目标：名称、选择、强度、
   加载状态和返回；桌面工具负责转换。参见 [机内体验设计](CAMERA_LUT_UI_PLAN.md)。
2. **按型号建立执行证据。** 继续用锁定的 E-P5 官方 1.8 MAIN、原厂调用帧、
   有界内存与异常场景建立证据。本轮把 ART 页面探针推进到真实 GUI 数据复制，
   不再在这个服务边界直接返回成功。
3. **分开报告组件、模拟和真机。** 本轮报告固定写明合成内存、模拟同步/通知和
   `physical_camera_test=false`，不将 36 个 CPU 场景等同于可刷固件。

## 本轮不引入的部分

浏览器完整相机模拟器、胶片编辑器、颗粒/光晕和双启动属于独立工程。现有公开资料
不能证明 E-P5 有兼容入口；增加这些功能也不能解除当前 GUI/文件任务/图像缓冲的
接入阻塞。本轮不引入 Fujimod 源码、依赖、协议命令、地址或可刷产物。

当前最直接的成果是 [ART GUI 数据交接契约](EP5_ART_DRAW_CHAIN.md)：已确认初始
表的三项容量与直接复制路径，接下来应恢复观察者生命周期、通知消费和文本资源，
再接现有 LUT 菜单快照。SD 后台任务、全幅像素/缓存及真机成片验收仍独立待办。
