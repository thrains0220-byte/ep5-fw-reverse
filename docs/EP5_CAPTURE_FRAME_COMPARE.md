# 用同帧 JPEG 核对已导出的 4:2:2 像素

准备一份已正常导出的 8 位打包像素文件和同一曝光、同一显影状态的参考 JPEG。两者应有相同的存储宽高和裁切，JPEG 使用原始像素方向。记录文件来源、显影设置、宽高及已知行距，以便区分机身导出数据与电脑生成的输入。

```powershell
python tools/compare_capture_frame.py frame.yuv same-shot.jpg --width 4608 --height 3456 --stride 9216
```

`--stride` 的单位是字节，紧密排列时可省略。带填充的文件可以保留或省去最后一行的尾部填充。比较器最多抽取 65,536 对相邻像素，分别按 YUYV、UYVY、YVYU、VYUY 解码，比较全范围与视频范围、BT.601 与 BT.709 的 16 种组合。两份输入的 SHA-256、每种组合的 RGB 平均绝对误差、像素对误差的 95 分位及四个象限的结果均写入标准输出 JSON。

`candidate` 表示本对文件中有一种组合同时通过亮度跨度、色彩变化、绝对误差和区域一致性检验。次优方案的平均误差须至少多 1 个 RGB8 色阶，且至少多出最佳方案误差的 25%。灰阶、色彩单一、参照错位或多种组合难以分辨时，报告返回 `uncertain` 与原因。退出码 0 表示有候选，1 表示不确定，2 表示文件、尺寸或调用有误。

这些阈值是保守的工程判据。内容几乎相同的相邻曝光仍可能相互匹配，可靠的同帧来源要由原始导出记录确定。从 JPEG 在电脑上重建的 YUV 只能检验转换过程。E‑P5 原生帧格式仍待有来源的配对输入核实。合成回归覆盖全部 16 种格式、有行填充、灰阶、弱色彩、错帧和局部不对应。
