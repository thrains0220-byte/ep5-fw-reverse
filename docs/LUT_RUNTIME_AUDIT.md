# E-P5 1.8：能否用 SD 卡更换多个 ART 的 3D LUT？

> 本页保留原厂能力研究的证据边界。2026-11-13后续已实现独立C加载器并通过7项宿主测试，但mode3机内集成仍失败；“缺装载器”应理解为缺少已验证的机身接入，不能忽略已有独立实现。[最新核查](LUT_PROGRESS_2026-11-13.md) · [后续执行计划](../plans/EP5_LUT_DELIVERY_PLAN.md)。

**原厂参数导入路径不能直接导入一张标准 17³ RGB16 LUT；当前项目也没有可安装的通用 LUT 运行时。** 这次确认了两个可以复用的 E-P5 原厂能力：按路径读二进制文件，以及在多个 ART 选择被合并前读取「模式＋变体」。二者之间仍缺装载器、运行时内存和经过验证的图像处理位置。

## SD 参数覆盖与文件服务是两条路径

原厂 `0x7e27c4c9..0x7e27c4db` 传入 FAT 目录 `PARAMDT`、匹配名 `CP??????CSV` 和服务类型 2。`0x7e141977 → 0x7e13fe11` 把记录写入点设为 `0x603c9f28`，把该次全部覆盖记录的可用空间设为 **8,188 字节**。行回调 `0x7e13ffa0` 读取参数 ID 和数量，由 ID 的低位求元素宽度，加 4 字节记录头并对齐，再检查、扣减剩余空间（`0x7e13fff1..0x7e140017`）。最后安装参数索引。它可以存放数组，并非只能存一个标量；但一张未压缩 17³ × RGB × 16 位的表就需 **29,478 字节**。更小的表或压缩表示也需要真正读取它并改变成像的消费者，目前没找到这样的 ART 消费者。既有探针仅证实原厂 getter 在合成环境里可以读到指定参数，不能从该例推出图像变化。[参数证据](FINDINGS.md)

另一个发现是常规文件接口，地址和参数均从 **E-P5 本机原版**取得：

| 文件服务 | 原厂 ABI（MN103） | 调用证据 |
|---|---|---|
| 打开 `0x7e291515` | `A0=路径, A1=模式`；返回 `A0=句柄`，零表示未打开 | `face_dbg_load` 在 `0x7e3d2fa8` 打开 `C:\TEST0000.RAW`、模式 `r`。另一个原厂调用 `0x7e41ad1b` 使用 `rb`。 |
| 读 `0x7e2915ea` | `A0=目标缓冲, D0=元素大小, D1=数量, A1=句柄`。对 `D0=1`，返回 `D0` 可按字节计数。 | 前者在 `0x7e3d2fc7` 请求 307,200 字节，后者在 `0x7e41ad42` 请求 8,192 字节。底层 `0x7e296dcd/0x7e296dd9` 将两个数相乘。 |
| 关 `0x7e291557` | `A0=句柄` | 两个独立调用点 `0x7e3d2fd4`、`0x7e41ad4e`。 |

三个封装都先调 `0x7e2914f1` 选择直接执行还是走带回复的服务消息；后者的服务单元为 `0x22`，打开/读/关操作分别为 `0x10001/0x10005/0x10002`。这不是允许任意任务在持有 ISP 或文件队列资源时同步调用的证据。调试函数的固定目的地址属于它自己，不能当成空闲 LUT RAM。字符串里的盘符 `C:` 也不是已证实适用于所有模式与介质挂载状态的契约。

**新 CPU 实验：** 从 `0x7e3d2f90` 开始执行原厂调试函数主体、上述三个原厂封装及其返回路径；只替代日志、后端选择，以及实际文件系统或消息服务的返回，所有模拟写入均限于合成栈。直调与消息两种分支各覆盖完整读取、打不开、只返回 7 字节，六项均通过。打不开时原代码返回 -1，不再读或关；**只读到 7 字节时仍关句柄并返回 0，与完整读取相同**。所以新加载器必须验证精确长度、格式与完整性；不能借用该调试函数的成功码。此实验没有读真实 SD，没有把文件内容注入相机。

## 多槽不能按滤镜结果码单独选择

`0x7e3ed3ad`、`0x7e3ed3b1` 读取原始设置 `+17471`（PictureMode）和 `+18147`（变体），送入原厂 `0x7e3fcb10`，其结果才写入 ART packet `+6`。以原版指令执行如下 39 组输入；日志服务被替代，选择器与跳转表未替代。列中「—」为原厂返回 `0xffff`。这是函数返回值；没有据此假定每一列都是菜单可选项。

| PictureMode | 变体 I | 变体 II | 变体 III |
|---:|---:|---:|---:|
| 1（非 ART 对照） | — | — | — |
| 100 | 70 | 102 | — |
| 101 | 69 | 69 | 69 |
| 102 | 71 | **145** | — |
| 103 | 72 | 72 | 72 |
| 104 | 74 | 104 | — |
| 105 | 73 | 106 | 108 |
| 106 | 86 | 86 | 86 |
| 107 | 85 | 167 | — |
| 108 | 91 | 91 | 91 |
| 109 | 96 | 165 | — |
| 110 | **145** | **145** | **145** |
| 111 | 75 | 75 | 75 |

例如 102/II 和 110/I 对应同一个输出 145。只看 packet `+6` 会让两个槽误用同一效果。运行时应在按原始模式、变体及来源识别后，把选中的槽和经过验证的 LUT 版本绑定到本次拍摄。替换模式还要阻止原厂另外叠色：对于针孔的模型案例，`+6=0` 且附加效果清零会保留原生 RAW→YC 转换、去掉针孔；尚未证明对其它模式及真实队列都成立。否则会把 LUT 加在已有 ART 变色、暗角或模糊之后。

## 保留全尺寸 RAW+JPEG，还差哪些环节

| 问题 | 已有证据 | 仍须解决 |
|---|---|---|
| LUT 放在哪里 | [链接布局](../firmware/ep5_art_entry.ld)的候选区仅 32,752 字节。含一张 29,478 字节 LUT 的实验模块 31,886 字节，余 866。启动代码构造的读取区间覆盖这个位置。 | 两张 LUT 本身要 58,956 字节。把多个槽放 SD，只让所选 LUT 驻留，是可行的容量设计；擦除内置表会释放空间，但不能因此把代码或只读区当成运行期可写的安全内存。需有跨任务有效的分配/释放、读成功后再公布、拍摄期间不替换或释放。 |
| JPEG 在哪一步处理 | 原版模型生成 4608×3456 存储几何，申请 **31,850,496 字节**（每像素两字节），并将相同地址传给原厂 JPEG 请求。在这个缓冲处理，然后让原厂 JPEG 编码一次，不需要缩图或先编码再解码。[原厂几何与分配](NATIVE_CONTRACTS.md) | 证明完整拍摄调用链中的生产者已经写完且不再写。当前适配器假定 Y0/Cb/Y1/Cr、BT.601 全范围；2 B/像素不能证明字节序、矩阵、范围、色域或 DMA 可见性。需同源样片或原厂编码/ISP 证据、实际缓存同步与所有权。 |
| 选槽与完成、重放 | [实验入口](../firmware/ep5_art_entry.c)检查接收状态、固定 token 1、packet 指针；记录 context 和 buffer，JPEG 前消费一次，释放前清空。 | token 不是逐拍 nonce，context 和地址均可复用；旧回复可能误授权新照片。现有 LUT 路径没有选槽判定，也没有消费者回显的独立请求号。应证明串行的提交/回收或使用发出、回复、释放都能核对的唯一序号；分开主 JPEG、预览、普通模式、回放、电影和 ORF。 |
| 延迟、取消及画质 | [C 色彩核心](../firmware/film.c)逐行执行；可传进度回调，开始前取消不会改图，处理中取消返回 `EP5_FILM_DISCARD`。当前机身适配器以 `NULL` 调用，返回值未处理。 | 80 像素的合成测试不等于约 1593 万像素的快门性能。须测看门狗、调度、拍摄/关机竞争；发现取消时不能把半处理缓冲交给 JPEG。完整验证包括原始 ORF、单次原厂编码、图像边缘/尺寸/文件与同源对照，以及失败时保持原厂保存。 |

一条可验证的开发顺序：先用固定的 SD 包格式，在非拍摄工作任务中验证精确读取、短读/坏校验/换卡回退与已发布内存的寿命；再分别打通「带槽的单次资格 → 已完成的全尺寸 YC → 一次原厂 JPEG」与原厂中性渲染。每个环节能单独验证。Windows 上导出 SD 包只完成第一步的**文件生产侧**，不等于官方 1.8 已经认识这个文件。

## 离线复核

```sh
python tools/audit_lut_runtime.py
python3 tools/audit_lut_runtime.py --execute
```

第一条是纯 Python 静态检查。第二条还要求 C 编译器和仓库使用的固定版本 MN103 引擎，重跑 6 项文件调用和 39 项 ART 选择器案例。输入可用 `--main` 指定；只接受官方 1.8 解包的 MAIN SHA-256 `dfe255e4d5a43329712c1fdfd6861ee1f3ef54a268b6096628bf045d8cc590df`。不生成升级包，不访问相机。[文件服务探针](../tools/ep5_lut_file_probe.c)仅复用 CPU 指令实现，没有使用其他机型的文件系统、设备地址或 ISP 模型。
