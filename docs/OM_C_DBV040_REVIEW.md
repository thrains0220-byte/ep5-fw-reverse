# OM-C / db firmware 0.4.0 检查记录

检查日期：2026-11-11。用户指定版本：[dbv0.4.0](https://github.com/azqeurio/om-c-firmware/releases/tag/dbv0.4.0)。本次阅读发布资料并静态检查其 Windows 包；未运行应用、访问相机或写出升级镜像。

## 结论

这个项目确实包含与 E-P5 直接相关的补丁记录，但 E-P5 功能是松下镜头 A/M 光圈环支持，不是胶片模拟。记录针对 E-P5 1.8，与本项目官方基线完全一致。其 9 项原始字节约束全部匹配，独立在内存重建的升级容器 SHA-256 与包内预期输出一致。

对本项目最有价值的是具体代码空洞候选、跳转/返回写法、版本约束和容器输出校验。它没有替我们完成颜色处理路径，也没有提供已经实机验证成功的 E-P5 常驻加载器。

## 实机反馈的边界

[官方反馈页](https://db-firmware-support.vercel.app/overview)的机型目录包含 E-P5 1.8。检查时[公开聚合接口](https://db-firmware-support.vercel.app/api/reports)给出：E-P5 A-mode、M-mode 光圈环各 1 条反馈，均为失败，版本均是 **db firmware 0.3.2**。0.4.0 包内的反馈快照也保留了这两条失败计数。

不能把旧版失败反馈当作 0.4.0 必然失败，也不能把 0.4.0 的候选记录当作实机成功。包内 E-P5 验证字段明确是 `hardware_boot=false`、`physical_dji=false`，仍需整机验证。

## 对 E-P5 胶片固件的实际帮助

1. **可直接复核的空间候选。** 独立扫描官方主块，确认 `[0x7e128010, 0x7e130000)` 连续 32,752 字节为 FF。第三方使用其中前 2,139 字节，给我们的常驻代码布局研究提供了具体位置。填充不证明运行期无人使用，需要继续追踪启动装载、RAM 写入和任务访问。
2. **体积约束更明确。** 当前本项目的测试用色彩引擎二进制为 2,567 字节，单个 RGB16 LUT 为 29,478 字节，两者合计 32,045 字节，距该区域长度只余 707 字节。这只是初步预算，尚未计入实际 veneer、配置、缓存/调度处理及对齐，不能据此认定已经装得下完整功能。
3. **输出容器的复现参照。** 同一原版输入、相同补丁记录经过我们独立容器工具得到相同输出 SHA，为后续正式升级文件的字节约束和构建核对提供了有效样例。
4. **仍由本项目完成的部分。** 图像缓冲区生产/生命周期、色彩编码、完整图像处理接入、机内选择、代码/数据布局、实机画质及恢复仍未被此版本解决。

当前使用者机身运行的是尚未识别的历史修改固件，不能直接把上述原版偏移应用到该运行镜像。后续可利用这里的可验证事实推进我们自己的实现，不能把光圈环候选固件当作胶片固件交付。
