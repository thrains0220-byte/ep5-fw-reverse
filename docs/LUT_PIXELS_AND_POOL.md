# E-P5 1.8：YC 像素和 ART 内存池

两条 E-P5 原厂 CPU 绘图路径都把一对像素写成 **Y0、Cb、Y1、Cr**，黑白亮度为 0 和 255。针孔 ART 第三道处理把全尺寸待编码的图像地址交给同一布局的图像请求；这个请求中的源和目的有区别。现有证据仍不足以把绘图用的矩阵、输入色域和采样位置直接赋给每一种静态照片。机内通用 LUT 仍未达到可刷状态。

在克隆了固定版本 CPU 模型、已有 C 编译器的开发环境，从仓库根运行 `python3 tools/audit_lut_pixels.py`。[探针](../tools/ep5_lut_pixel_probe.c)只在 PC 内存中执行 SHA-256 为 `dfe255e4d5a43329712c1fdfd6861ee1f3ef54a268b6096628bf045d8cc590df` 的 E-P5 官方 1.8 MAIN。除合成入口外，运算和填充、针孔请求字段填写、内存分配分派、返回值及出参均由原指令执行。诊断打印返回、绘图缓冲地址、最底层内存池结果是模型。不运行 ISP 或访问相机；不需要 MN103 交叉编译器。

## 两个能逐字节重现的写入器

电影矩形代码 `0x7e3baa9e` 从结构的 +16/+17/+18 读 RGB8，乘加后，`0x7e3bab2a` 开始写满 1024 个 32 位字。随后原指令把这块内存放入图像请求 +0，将 +194 置 21。在回放路径，`0x7e60f261` 从另一种结构的 +72/+74/+76 读取三个 u16 分量，`0x7e60f2c6` 调用矩形绘制，`0x7e60b863` 真正写像素。在 8 像素跨度的缓冲内，测试让其只写两行四列，并逐字检查其余内存及边界哨兵。

| 给定的 RGB | 两条路径写出的同色像素对（内存字节，从低地址到高地址） |
|---|---|
| 黑 / 白 | `00 80 00 80` / `ff 80 ff 80` |
| 红 / 绿 / 蓝 | `4c 54 4c ff` / `95 2b 95 15` / `1d ff 1d 6b` |
| 灰 128 / RGB(254,7,113) | `80 80 80 80` / `5c 8b 5c f2` |

原版整数式如下，右移为有符号算术右移。亮度没有减 16，也没有把纯白限制为 235；色度中性为 128。两段代码各执行 9 组颜色。它们绘制的是同色像素对，不能测出异色相邻像素在 ISP 中如何合成或定位色度。

```
Y  =       (19595*R + 38470*G +  7471*B) >> 16
Cb = 128 + ((-11056*R - 21712*G + 32768*B) >> 16)
Cr = 128 + (( 32768*R - 27440*G -  5328*B) >> 16)
```

## 到静态针孔和 JPEG 的证据边界

原版 `art_effect_20_pinhole` 经 `0x7e40115c` 装载 pass 表 `0x7e55657c`，第三个函数指针为 `0x7e40134a`。探针从已分配请求的 `0x7e4013b5` 开始，运行原厂 `0x7e40a065` 几何复制、`0x7e409725` 构造器，到 `0x7e401438` 提交前停止。4608×3456 输入得到请求 +106/+110 的 4608/3456；`packet+76` 指向的缓冲最终存到请求 +16，模式 +194 为 21，提交参数分别为请求、原始 packet、`0x40000` 与来源行号 `0x139`。真实 ISP 并未运行。

这不是按偏移猜测字段：官方记录端诊断打印在 `0x7e3f0e95` 把 +16 标为 `ulW1Addr1`，`0x7e3f1023` 把 +106 标为 `usInMemHw`，`0x7e3f1043` 把 +110 标为 `usInUseVw`，`0x7e3f13af` 把 +194 标为 `ucMode`。电影模块自身打印 `IMG_CTRL` 的 +0 为 `ulR1Addr1`，+16 为 `ulW1Addr1`，+194 同为 `ucMode`（`0x7e3af553/0x7e3af5cd/0x7e3afbdc`）。因此 21 是共同的**处理模式**，还不是已解码的像素格式枚举。原厂 [JPEG 请求探针](NATIVE_CONTRACTS.md) 已独立执行 `rec_art_make_prim` 获取同一个全局地址并传给 `0x7e3f4884`。现已证明 CPU 绘制源的编码、静态 ISP 的写目的、静态 JPEG 的读源；没有执行 ISP 实现或获得其未压缩色块，不能证明它在该输出端保持完全相同的范围、色域和色序。

## ART 所用内存池

原版分配全幅缓冲的调用点 `0x7e40a317` 把 `width*height*2` 传给 `art_buff_alloc 0x7e40a3fc`。探针以相同调用帧执行其模式 3 路径，传 D0=29478、D1=0、A0=指针出参、A1=合法原版诊断字符串，调用者栈 +4=模式、+8=诊断行号。外层经过 `0x7e40a498 → 0x7e23e0a2 → 0x7e23e0ff`。成功返回 0 并存储后端指针；这个分支若返回 NULL，外层将出参写零，返回 `0xffff`。释放入口 `0x7e40a4f0` 收 D0=原指针、D1=3，经 `0x7e40a530 → 0x7e23e0b0 → 0x7e23e2fd`。

连续发两个请求再释放两次，以及第二个请求失败、仅释放第一个的分支，都经原指令验证。另一个原厂记录分支 `0x7e3eaf63/0x7e3eaf82` 确实会在第一个尚未释放时向同一服务再申请 0x390000 字节，随后分别释放；这不是在 ART 全尺寸 RAW+JPEG 期间仍有 58956 字节空闲的证明。可用于实现带失败分支的活动表和暂存表，但暂不能将这些地址常驻：需要确定生命周期的所有者、切卡/取消/模式切换后的收尾、DMA/CPU 同步和实机最坏时延，或在证据不足时退回原厂。整个试验不占用调试缓冲、不落盘固件，不修改 RC2 配方。
