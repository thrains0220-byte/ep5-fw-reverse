# E-P5 机内 LUT 体验：设计与验证门槛

目标是在相机内选择 SD 卡风格、确认当前名称和状态，并调整效果强度；照片以全尺寸 JPEG 直出，保留 RAW。桌面工具负责导入和转换，不代替机内操作。这里是设计目标，不代表现有固件提供这些功能，也不保证原厂硬件一定支持全部交互。

## 现状

机身已验证的固定色度版本复用原厂 ART 项目和变体，保留对应原厂空间效果；不是 SD 三维 LUT。针孔 I/II/III 是一个原厂条目的三个变体，而不是三个可独立改名的菜单行。现有卡上索引中的短名称仅用于校验元数据，未接到相机文字绘制；强度来自卡上数据，不是机身滑块。机内 LUT 运行时目前只有 CPU 模型证据。详细范围见 [ART 审计](ART_SLOT_AUDIT.md)和[路线 B 进度](LUT_ROUTE_B_PROGRESS_2026-11-14.md)。

已增加 `firmware/lut_menu.{h,c}` 和 `firmware/lut_menu_index.{h,c}` 作为机内菜单状态核心的第一步：三槽固定容量、加载中/就绪/错误状态、代号防止旧读卡结果覆盖、光标移动、确认、返回，以及从 `INDEX.EP5` 发布固定容量名称/编号/强度快照。它现在已接入 cave 运行时的共享状态区；拍摄钩子通过代号前后校验读取已确认槽位的原子快照，加载中、错误或不一致时走原厂路径。它仍尚未接入 E-P5 的真实状态机描述符、绘制对象和文件任务唤醒，因此不能称为机身功能。

## 目标操作

1. ART 中进入“胶片模拟”，浏览卡上的风格名，选中即显示明确的当前选择；无卡、未配置、损坏和不兼容时给出可理解的状态，并恢复可拍的原厂路径。
2. 使用相机已有方向键、OK 和返回键调整效果强度并确认，取消不改变已保存选择；重启及换卡后的选择行为必须一致、可预测。
3. 首先实现静态照片 JPEG；RAW 保留。取景预览、录像、颗粒、光晕和色轮分别验证后再开放，不能通过菜单假装支持。
4. 卡上风格可替换，但不承诺拍摄期间热插拔：更新与重新读取的时机必须经过文件系统与资源寿命验证。

## 执行顺序及门槛

1. **可靠诊断**：只读研究 JPEG 请求、文件服务、任务上下文、目录行为和耗时；诊断记录不得猜测内存可读。离线探针覆盖多次拍摄及失败，独立审查后才考虑真机诊断。旧诊断包已撤回。
2. **图像链路**：确认像素格式、缓冲所有权、缓存一致性与全幅时间；先恒等表对照，再验证非恒等 LUT、RAW、取消和缺卡回退。尚未完成前不发布功能固件。
3. **菜单发现**：从语言条目 69/602 与 ART 选择机制入手，追踪项目表、事件处理、选项保存、绘制和文本生命周期；使用只读分析及可复现的 CPU 探针，不把内部编号当作可达 UI 项。
4. **有限名称验证**：先在模拟环境中以固定容量、拥有明确生命周期的缓冲测试名字、编码、截断、空卡和重绘；不得把 SD 数据直接作为指针。真机上验证布局、语言、切换和退出后，才可宣称动态名字可用。
5. **交互与状态**：验证按键事件和回退路径，分别加入选择、强度、错误状态和持久化；每项都有禁用开关，避免 UI 故障影响普通拍摄。无法安全扩展原菜单时，先使用既有 I/II/III 变体并如实标识限制，而非宣称完整浏览器。
6. **验收**：真实机身反复完成选择、更换卡数据、重启、缺卡/损坏卡、全尺寸 RAW+JPEG、连拍与取消；验证启动、关闭及官方恢复。只有证据齐全才发布并标记可用。

## 目前不能承诺的事项

还没有证明原厂 UI 能容纳任意数量的风格、绘制 SD 名称，或支持类似 S9 的新控件；也没有证明实时预览、色轮、颗粒或光晕能够在 E-P5 的性能与内存预算内工作。每项以代码与真机证据为准，不靠其他机型的地址或体验推断。
