# E-P5 机内胶片模拟 / SD LUT 直出：执行与交接计划

版本：2026-11-13 核查版。设备固定为 **Olympus E-P5，官方 1.8 基线**。本计划面向可从零接手的开发者；当前进度和本轮验证见 [核查记录](../docs/LUT_PROGRESS_2026-11-13.md) 与 [输入哈希/结果](../docs/lut-progress-audit-20261113.json)。

## 1. 目标、范围与发布状态

用户最终需要的操作链是：Windows EXE 导入网上的兼容 `.cube` → 预览、设置强度并选 ART 替换位置 → 写风格数据到 SD → 相机在对应 ART 位置生成全尺寸风格 JPEG，并保留 RAW。若原版不能加载外表，接受一次安装通用固件，此后换风格无需再改/刷固件。

第一版优先复用 **针孔 I/II/III 三个可达变体**。桌面其他槽只是拟用候选，须逐槽打通才开放；不先扩展原厂菜单条目数。任意 SD 短名动态进入机身 UI 是额外工作，不能把桌面改名当作已经改了机身。第一版可使用固定“LUT I/II/III”名称与工具中的风格对应表；如无法验证动态标签，就明确保留此限制。

画质要求：4:3 最大尺寸主 JPEG **4608×3456**，同次 ORF 完整保留，风格处理发生在第一次 JPEG 编码前；不能用内嵌预览、缩图或 JPEG 解码后二次编码冒充完成。处理时长可以较长，但必须可见、可取消、不会让相机失去可控退出能力。

第一版承诺的是逐像素颜色变换。`.cube` 不表达颗粒、光晕或空间模糊。现有输入只支持归一化 3D `.cube` 2³–65³、编译到 17³ RGB16，且要有可信的 sRGB→sRGB 声明；Log、shaper/1D 组合和未知基底不能靠改标签变得兼容。参考 S9 的风格管理体验，不承诺相同硬件实时取景或视频能力。

发布状态分为：`desktop-only`、`model-verified`、`hardware-diagnostic`、`hardware-functional-candidate`、`camera-verified`。诊断候选和功能候选必须分开构建、分开命名：前者编译时排除LUT像素写入、中性化ART packet和原厂回复缓冲预置，只允许已证明合法的元数据/生命周期观测，原厂成像路径照常执行；后者才可执行LUT。静态像素地址/容量/格式/完成时点或缓存/资源寿命未决时，**禁止生成功能性硬件候选**。最后一项必须有本台E-P5实拍、关闭和恢复证据；不能预先宣告新固件零风险或真机已可用。

当前相机保持官方1.8、USB断开。S0–S8的实现和构建工作在电脑完成，S9才验证功能候选。若S4/S5无法从离线原厂证据完成前置契约，功能主线停在该门槛；仅可准备独立的D诊断分支，待机主以后另行审阅并授权后取证，再回到S4/S5。用户目前要求先完成版本再刷机，因此本轮不启动诊断试刷。旧RC2授权和证据不自动覆盖诊断或新SD LUT运行时。

## 3. 固定约定与禁止再次踩的坑

### 3.1 MN103 调用约定只服从代码证据

以固定 CPU 实现 `external/em10-fw/emu/isa/mn10300.igen` 与 E-P5 原指令为锚点：设执行 call **之前**的 SP 为 `S`：

- `call target,[regs],N` 先在 `S` 存返回地址，按 mask 在 `S-4、S-8…` 保存寄存器，再使 SP=`S-N`。换 mask 不会把返回地址从 `S` 移走。
- `mov reg,(k,sp)` 访问 **SP+k**，不是减偏移，也不会因为超出“逻辑栈帧”而自动丢弃写入。
- `ret [regs],N` 先 SP+=N，按 mask 从其下方恢复寄存器，PC 从恢复后 `(SP)` 读取。
- 固定模型中的 `rets` 从 `(SP)` 读 PC；`retf` 恢复帧后使用 MDR。不能把三者互换。
- 原厂池探针以 `call [...],32`、调用前 `S+4=3`、`S+8=0x4e4` 成功；被调者的 `(36,sp)` 正是 `S+4`。mode 8/9 的检查是另一条条件路径，不能说 mode 3 不能分配。

上面只说明指令与已测的原厂调用，不给 GCC 包装器“照抄一组偏移”的处方。GCC 的前两个参数位置、第三/第四栈参数、指针返回位置、flushback 区、非易失寄存器，都要用小 C 调用者的反汇编及独立闭环测试逐项验证。

### 3.2 数据、内存与代码空间

| 对象 | 已固定 / 待确认 |
| --- | --- |
| LUT 数据 | 17³×3×2 = **29,478B**；红轴最快；小端 RGB16 |
| 两表最少数据空间 | **58,956B**，另算对齐、状态和服务栈；当前实现误申请 117,912B |
| 索引头 | `<8sHHII>`，20B，`EP5IDX02`，v2 |
| 索引记录 | `<HBBHHI16s>`，28B；模式/变体/flags/Q8强度/风格号/绑定CRC/短名 |
| LUT 头 | `<8sHHIII>`，24B，`EP5LUT01`；精确长度、编号及 CRC 全校验 |
| 路径 | 开发协议相对名 `EP5LUT/INDEX.EP5`、`EP5LUT/L0000001.LUT`；真机 SD 根/分隔符/挂载须另证 |
| 当前控制/状态 | 7×u32=28B；2资格字+4风格状态字=24B；以后只从符号/manifest取偏移 |
| 候选代码区 | 32,752B；当前模块4,444B；加完整默认表后超1,170B，不能直接拼接 |

索引绑定 LUT 内容 CRC，防止同编号混包，但不是安全认证。机身只读有界数据，不执行卡上代码。公开包不得包含第三方原厂整包或用户照片，默认风格使用原创或许可明确的素材。

### 3.3 默认风格和失败回退的产品优先级

以下是**待实现的第一版规则**，不是当前机身已具备的行为；需在S3/S7共同写进协议测试：

| 条件 | 预定行为 |
| --- | --- |
| 有正常SD介质，但尚未配置`EP5LUT`目录/索引 | 指定的一个默认槽使用内置原创风格，其他槽保留原厂；这实现首用不依赖电脑 |
| 有完整有效索引，当前槽绑定有效外表 | 使用该外表和该记录强度；覆盖默认槽的内置风格 |
| 有完整有效索引但当前槽未绑定，或记录强度为0 | 保留对应原厂ART；用户由此禁用默认/外部风格 |
| 索引损坏、所绑定表缺失/损坏、池/加载失败 | 对本张回退对应原厂ART并提示；不偷偷沿用旧表或换成内置风格 |
| 没有SD介质/介质不可写 | 保留原厂无卡/写卡错误处理；不能承诺此时仍能保存照片，资源必须正常收尾 |

必须区分“索引不存在”和“介质/读取出错”；当前`open==NULL`不能可靠区分时，先补服务契约，否则不能实现上述默认优先级。完整原厂回退还要满足下一节的阶段约束。

### 3.4 先证明失败路径

缺卡、坏表、内存不足、加载超时、旧回复、取消和关机竞争都要有确定行为。若已经中性化原 ART packet 或改了像素，不能简单“跳过 LUT”就声称回退原厂成功。必须在不可逆修改前确定可继续，或保有可恢复的源/请求；中途取消的缓冲不得进入 JPEG 编码。

7. 对中途取消采用安全源/目标或可靠丢弃并重显影；不能把已修改的半帧继续编码。切模式、换卡、关机也走同一清理协议。

**验证矩阵：** apply/identity/half/zero；无索引/无LUT/短读/错误EOF/CRC/版本/尾随数据/同编号混包；错误槽/来源；超时/短回复/错token/旧完整回复/地址复用/重复JPEG；各阶段取消/释放/池失败；direct与message均覆盖。

**验收：** 每一条路径都有可断言的 packet/像素结果、编码次数及资源清零；加载失败后下一张仍能正常拍；完整集成探针至少从发送到释放通过，不再只看阶段标记。

**撤回：** mode3保持关闭，恢复原厂路径；禁止把未通过的集成状态纳入更新包。

### S4 — 证明真实静态图像契约和颜色正确性

**文件：** `film.c/h`、`lut.c/h`、图像/原厂审计、画质验证工具。依赖 S3。

**任务：**

1. 从真实分配/生产者取得基址、容量、stride、有效矩形和所有权，接到每张照片；不能沿用测试地址 `0x12000010` 或把“request里的地址”直接当分配容量。
2. 串接原厂RAW→YC完成到JPEG读源，证明没有后续ISP/DMA并写；分清主JPEG、预览、回放、RAW编辑和视频。
3. 确认静态输出的字节序、全/限范围、矩阵、色域、色调阶段和色度采样位置。两条绘图器的Y0/Cb/Y1/Cr BT.601满范围证据只是线索，不能直接覆盖静态ISP。

6. 核查32位整数范围、舍入与色度共用造成的偏色；保留现有identity残差策略，使用合法输入时恒等表须逐字节不改YC缓冲。真实ORF与主JPEG文件随后单独验收。

**验收：** 地址/容量/格式/完成证据成表；模型与独立参考一致；无缩图、无越界，恒等无改动；色彩误差报告有输入域、样本、指标及限制。静态像素契约未决必须阻止`hardware-functional-candidate`，而不只是阻止最终`camera-verified`。

**撤回：** 拒绝未知格式和模式，保留原厂输出；不可用低尺寸或二次JPEG路线顶替。
