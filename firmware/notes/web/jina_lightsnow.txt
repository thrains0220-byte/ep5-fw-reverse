Until somebody discovers the new naming scheme or unless somebody offers you a pointer to a preserved version of the existing firmware file, you won't be able to use the SD method to update the firmware. Lightsnowdev never contained the actual binary. Instead, it pointed to the images on the system '**dl01.olympus-imaging.com**'. Note, Lightsnowdev has not been updated in a while, and some of the newer firmwares that were released were not listed on the system.

Presumably this action is part of the required required cleansing of using the name Olympus that OM Systems has to do (i.e. at some point as per their contract, OM systems had to turn off '**dl01.olympus-imaging.com**'.

People that have not updated OM Workspace, OM Updater, etc. recently probably also discovered today that they will need to download new versions of these programs (i.e. the updates for OM Workspace, etc. was also on the **olympus-imaging.com** site). I recall chatter going out that said people had to update OM Workspace, OM Updater before April 1st (i.e. the new versions look in the new place). Here is the warning OM put on their system:

> Depending on the version of our application, the update function will no longer be available from April 2024.  
>  We recommend that you update your application to the latest version by the end of March 2024.  
>  If you cannot update the application already, download the latest version from the download page and install it again.

I tried getting firmware from the new system ('**dl01.om-digitalsolutions.net**'), but the name used is different than the name used on '**dl01.olympus-imaging.com**'. So somebody is going to have to figure out the new naming scheme.

What you need to do is rig your system to trace outgoing http requests, looking for filenames. There are various ways to do this, but since I don't run Windows or MAC, I can't do this. Then run OW Updater, etc. to update firmware, and see the pathname that is downloaded. From there, we can probably deduce the general naming scheme.

[@PhotoDmiK](https://www.mu-43.com/members/25822/) , thanks so much for digging into this. You are an absolute legend. This is what I did to get the request.

1. I copied the contents of all.xml from the post you wrote and saved it onto my working directory.  
 2. I updated the values from the master spreadsheet, changing the values of OLYE143000000000 (which identifies requests the link for OM-1 Mk. I)  
 to OLYE097000000000 (since 097 is the identifier for the E-M5 Mk I).  
 3. After running the updated curl request with the updated all.xml, a file called all_do.xml is downloaded  
 4. From the all_do.xml, I located the <url> element in the XML which contained a link to the BIN file with the appropriate required attributes: Expires, Signature, and Key-Pair-Id. The only caveat is that there is de-entitized HTML for the ampersand symbol showing &amp instead of the actual & character. A find and replace for &amp ->& will result in a working URL.  
 5. I copied the entire URL, and the file was downloaded.

Update:  
 6. After downloading the BIN file, I created a directory in my SD card called "DCOLYMP"  
 7. I renamed the BIN file with the appropriate SD card title of "E0979999.BIN" for my E-M5 Mk I.  
 8. After I popped it into the camera, held down OK, powered on, saw the orange light, orange light stopped flashing, power off!

I'm updated!! Cheers for your help guys. It is much appreciated.
